# Agent 团队职责协议候选版

本版服务于大型复杂任务的职责设计，依据用户提出的战略引领者、军团长、监督者、执行 Agent 和独立验证职能整理。版本为 v3，已根据一次独立冷读补充成功标准、证据版本、任务关闭和角色接替责任。它是待运行检验的候选设计，当前实验只覆盖其中一部分。

## 决定对象与责任

| 职责 | 决定对象 | 必需输入 | 输出与责任 |
| --- | --- | --- | --- |
| 战略引领者 | 用户授权内的阶段目标、里程碑、优先级、价值取舍与是否继续 | 用户意图和授权、实际成果、环境变化、资源、关键未知 | 带成功条件和停止条件的里程碑，目标变更及理由；不能以意图推断扩张用户授权 |
| 军团长 | 当前里程碑的实现方法、分工、依赖、集成和交付准备 | 当前生效里程碑、任务进度、实际产物、验证证据和监督发现 | 可执行任务、集成产物、交付证据、未解决项；对完整用户路径负责 |
| 监督者 | 需要哪一方回应的偏航、阻塞、遗漏或观测失败 | 当前目标、授权、活动记录、产物和实际运行状态 | 证据性发现、责任人、回应与升级状态；普通发现不自动产生改目标或暂停权 |
| 执行者 | 已分配任务内的局部方法和产物 | 命题、输入、依赖、约束、完成标准、可修改范围 | 产物、依据、验证请求、已知问题和跨任务影响 |
| 验证者 | 如何检查实际结果是否满足当前标准 | 用户授权及仍有效的约束、当前生效版本的里程碑与验收标准、对应版本的产物和环境 | 检查范围和原始证据，通过、失败或未验证；证据不足应保留未知 |

用户是授权来源。系统在持续授权内可自行推进多个里程碑；扩大授权或改变用户保留的目标时，由用户决定。上述职责可以按任务选择独立实例；不要求每个简单任务都启动全部角色。

战略、军团长、监督与验证都应能回查原始目标和有效变更。任务摘要用于分工时，应带原文位置与版本；接手者发现摘要与原始约定不一致时，先核对有效约定，不以摘要自行缩小成功标准。

## 目标变更与事实争议

战略目标变化经军团长进入当前任务版本，并明确旧任务继续、调整或取消。执行者只依据当前生效的任务约定行动。战略与执行者可以共享证据，改变执行安排时须有明确负责人。

方法与分工争议由军团长在现有约束内决定。目标与资源冲突交战略在授权内调整。事实争议由实际观察、复现和复测处理。验证者的独立位置不使其判断免于复查。

战略在授权内制定和修改里程碑成功条件。军团长将这些条件细化为执行任务完成标准，可以调整实现和执行团队的自检安排，但不得削弱上层成功条件。独立验证的方法与覆盖由验证者决定；军团长可以提出补验或复核要求，不能以进度或局部自检代替独立验证结论。涉及里程碑成功条件变化时交战略决定；涉及用户保留目标或约束变化时交用户。每次变更均形成新版本，并核对哪些已有证据仍然有效。

验证失败与允许带限制交付分别记录。接受残余问题需要对应决定权，不能将失败记录改写为通过。新的产物或环境版本须有对应的有效证据，旧版通过结果不能自动证明新版满足目标；检查可以依据影响范围安排，无需机械全量重跑。

验证结论绑定用户授权版本、里程碑与任务标准版本、产物指纹和环境。原始目标用于追溯变更历史；判断使用当前合法生效的标准及持续有效的约束。判据发生合法变化后应给新结论，原先失败及其处置仍保留。

## 监督闭环

监督覆盖战略、军团长、执行和验证。每条需处理发现包含预期、实际、证据、影响、责任人和回应状态。责任人可采纳或以证据驳回。持续无响应时，监督向拥有该类决定权者升级；涉及战略越权或持续不回应时，可直达用户。

监督状态应区分推进、正常等待、阻塞和无法观察。长时间工具调用需要根据进程句柄、实际进度和预期时长判断，不能仅凭一段时间没有消息重启。监督自身的最近观察时间与覆盖范围应可见。

## 验证与交付

执行者可以请求独立验证。军团长和监督者也可依据遗漏或集成风险提出验证需求。验证者能直接读取当前目标和真实产物，独立选择检查，结果无需经过执行者筛选即可进入交付判断。

局部结果由执行者交接，完整产物由军团长组织集成并取得用户路径证据。验证者负责观察和评价，军团长在授权内决定交付，战略判断里程碑价值与下一阶段。没有要求每次交付都新增一套串行审批。

军团长可接受任务约定容差内的残余问题并交付。影响里程碑成功条件的问题交战略处理，影响用户保留目标的问题交用户。军团长依据有效完成或停止条件关闭有限执行任务，并分别记录产物是否交付、目标是否达成、为何停止。已交付但目标未达成时保留未达成状态，不能标为成功。战略依据上层目标与授权判断项目或持续计划是否结束；一次执行任务结束不自动生成新里程碑。

## 被启用角色的失效与接替

启用某项职责时，记录失效信号的观察者、接替决定者、替补与无替补时的去向。普通有限任务同样适用，不能只为持续服务和外部动作记录替补。

运行层提供会话、进程、最近活动和消息投递状态；语义异常由监督者提出。验证或执行职责失效后，军团长组织接替；军团长失效后，由战略按既有授权组织接替；战略失效或决定者也不可达时，按预先授权的替补规则处理，否则交用户。监督者的观测失效由运行层状态检查呈现，战略或已指定的运行负责人组织恢复。没有配置持续状态检查的部署，只能声称有快照监督。

无替补时，已有独立授权且不依赖缺失决定的工作可以继续。无人承接的集成、验收、交付决定保持待决，升级到指定上级或用户。接替者读取同一版本约定和未闭合发现；更换验证者不能删除此前不利结果或借机降低标准。

## 持续服务与有限任务

持续服务单独保存目标、期限、来源、健康状态和运行责任人。军团长负责运行与事件处理，战略负责授权内的服务目标调整。运行层承接持续监听、事件保存和唤醒。

子事件任务完成不自动终止服务。服务按用户停止或到期条件结束。监听断线应记录观测缺口。负责人不可达时，按事先授权的替补处理；无替补则保留事件并报告服务降级。

## 负责人不可达时的外部动作

启动任务时明确哪些动作可独立继续，哪些需要当前有效放行。记录决定者、替补路径、适用版本及有效期。

候选默认政策是新的不可逆外部动作需要有效放行，已经明确授权独立继续的动作可继续。负责人失联本身不撤销仍有效的既有放行。运行层执行既定规则，监督者提交证据和升级，不临时自行扩张权限。

已提交但结果不明的动作先查实际结果，再决定后续。没有负责人且无有效放行时，依赖放行的新动作等待，其他已有独立授权的工作可继续。这是候选政策，不能解释为对某项真实外部操作的授权。

## 现实任务对本设计的约束

- 高耦合研发需要检查任务是否实际可分。Anthropic 的编译器实验中，多个 Agent 曾被同一 Linux 内核编译错误阻塞并互相覆盖，改进来自重新设计可隔离问题的测试环境。职责名称本身不能提供这种分解能力。[编译器实验](https://www.anthropic.com/research/building-c-compiler)
- Cursor 的长期工程实践支持明确规划和执行责任，同时记录额外集成角色造成瓶颈。集成责任需要被承接，独立集成实例的收益仍需依据具体任务判断。[Cursor 实践](https://cursor.com/blog/scaling-agents)
- 事故响应要求清晰的即时指挥关系与操作责任。这为方向变更和监督干预的边界提供参照，尚不能证明相同人类组织安排对 Agent 必然有效。[Google SRE](https://sre.google/workbook/incident-response/)
- 独立验证需要能选择检查范围、方法并报告结果。NASA 的制度提供机制参照，本设计没有据此要求所有任务照搬航天审批。[NASA IV&V](https://www.nasa.gov/ivv-overview/)
- 体验创作还依赖真实受众反馈。Anthropic 的游戏实验中，角色和层级的提示变化未明显改善体验；本设计需保留评价未知，不能由分工齐全推出作品有效。[多 Agent 实验](https://www.anthropic.com/research/multiagent-systems)

上述材料分别提供设计约束，均未直接验证本候选协议的整体效果。

## 当前验证地位

前一轮独立桌面检查覆盖八个情境，发现持续服务责任和负责人不可达时的处置欠定义。新增对应两条后，独立复查确认原缺口得到文义修复，并回归了版本证据和正常等待情境。

当前工程样题用于检验独立实例能否实际交接、修复与验证产物。样题故障由主持人构造，运行记录与结论见同目录实验报告。总体成功率、长期监督效果、成本收益、共同认知偏差和跨领域能力仍需后续实测。
