# Superagent 职责边界与适用性审计

## 当前层结论与边界

本次只展开研究任务“先把职责边界和适用性审计清楚”。输入是用户提出的四类结构、独立验证的补充设想、引用对话《拆解任务收敛失败》中关于任务收敛失败的背景，以及 `.cursor/drafts/superagent design/role-research/DESIGN-v4.md`、`role-research/REPORT.md`、`role-loop/DESIGN.md` 和 `role-loop/REPORT.md` 中的候选协议与工程记录。

本层得到的是一份可用于继续设计的边界模型与启用条件。它还不能证明这套结构在不同任务族中的总体收益，也不进入 `hyperagent` Skill 的提示词、调度协议或运行器实现。

当前最重要的修正是：四类职责不应被理解为每个任务都必须常驻的四个 Agent。主人公是有限任务的默认负责人。有限任务指有可验收终点、可以定义关闭条件的单次任务。其他职责按任务的收敛风险、并行可分性、独立验收需要和持续运行特征启用。独立验证是对执行产物进行独立判断的能力，是否单独起一个 Agent 由风险与证据要求决定。

## 当前根契约

- 当前根路径：`root/superagent-boundary-fit`
- 展开模式：初始化
- 上游输入状态：已经存在一套四类职责的概念草案，另有资料将独立验证单列为第五项职责。已有工程样题和真实源码研究支持部分边界，但没有跨任务族的效果证据。
- 本节点承诺的输出状态：形成每类职责的决定对象、输入、输出、不可越界事项、交接关系；识别不适合完整分工的任务族；明确哪些问题要求改结构，哪些只要求按条件启用或补运行保证。
- 下游消费者与用途：后续的职责协议、启用判定、运行监督设计和 `hyperagent` Skill 设计。
- 上层目标、取舍与不可牺牲项：让复杂任务更接近可接受的终止状态；保持用户目标和授权边界；保留事实、判断、验证结果与未知；不能用“角色齐全”替代实际收敛和用户路径验收。
- 新增现实信息：引用对话把问题指向推进能力与终结能力的分离，并指出边界扩张、返工循环、外部等待和最终决策回避会让任务长期不收敛。现有资料记录了一次工程样题和一次真实源码研究，但没有随机化对照或长期运行证据。
- 假设、未知与范围外：暂假设团队可以保存版本化任务约定和验证证据。未知包括角色数量的成本收益、真实监督的持续可达性、共同偏差、并发写入、外部服务失败和跨领域适配比例。完整 Skill、运行器、权限系统和性能评估属于范围外。

## 本层心智索引

下列表格和任务族矩阵只记录当前层的边界与证据摘要，不展开 A-D 的内部子图。

### `root/superagent-boundary-fit/A` 把职责映射为决定对象与授权边界

- 本层作用：把“战略引领者”“主人公”“监督者”“具体做事 agents”从角色名称转成可检查的决定对象、输入、输出和权限边界。
- 输入边界：用户目标、授权、当前里程碑、任务状态、实际产物、验证证据和监督发现。战略角色不得仅凭内部推演扩大用户授权。
- 核心认知动作：区分目标和方法、事实和判断、局部产物和整体交付、观察和干预、执行自检和独立验证。
- 输出边界：一张角色边界表，说明谁对哪类决定负责，哪些变化必须上交，哪些任务可继续推进。
- 本层关系：当前根的第一节点，后续作为交接关系和适用性测试的输入。
- 放行信号：每个角色都能回答“我能决定什么”“我不能改写什么”“我的输出由谁消费”。
- 回开方向：若同一决定有两个有权生产者，或某项终止判断无人负责，回开本节点。
- 后续展开：需要用更多真实任务检查“战略判断”和“主人公综合判断”的分界，以及监督者的干预权限。
- 展开状态：本层已展开

| 职责或能力的承载方式 | 负责的决定对象 | 必须接收的输入 | 形成的下游状态 | 不得静默承担的决定 |
| --- | --- | --- | --- | --- |
| 战略引领者 | 在有效授权和既定停止条件内形成阶段目标、优先级、里程碑成功条件和是否继续的判断 | 用户意图与授权、阶段成果、关键未知、资源和环境变化 | 当前有效的目标与取舍版本 | 不得把自己的偏好变成用户目标，不得替主人公决定具体实现，不得以“监督发现”直接改写目标。改变用户保留目标或不可逆状态须交回用户或真实授权者 |
| 主人公 | 当前目标下的任务理解、拆解、分工、依赖、集成、交付准备，以及在有效授权和验收证据范围内形成有限任务的关闭与交付判断 | 有效目标版本、任务现状、执行产物、验证证据、监督发现 | 可执行任务网络、组合产物、交付证据、未决事项 | 不得削弱上层成功条件，不得代发独立验证结论。完成交付不等于目标达成，除非成功条件已有证据满足 |
| 监督者 | 当前推进是否仍朝有效目标前进，是否发生阻塞、偏航、遗漏、失联或观察缺口 | 目标与授权、活动记录、运行状态、产物、证据和历史发现 | 带证据的发现、责任人、回应状态、升级或复查请求 | 不得因观察到异常就自行改目标、暂停一切工作或授权不可逆外部动作 |
| 具体做事 Agent | 已分配局部命题的方法选择、局部产物和局部自检 | 命题、输入、依赖、约束、完成标准、可修改范围 | 局部产物、依据、自检结果、已知问题、验证请求 | 不得扩大范围、改变共享目标、替整体任务宣布完成 |
| 独立验证能力 | 如何依据当前标准检查实际结果，及检查结果是否成立 | 有效目标和标准版本、对应产物、环境、原始输入和可复现实验 | 独立检查范围、原始证据、通过、失败或未验证结论 | 不得由被检对象筛选证据或把失败改写为通过；它不是固定第五角色，是否独立成 Agent 由风险决定 |

这里把四类职责与一项跨角色能力并列比较。独立验证能力不是必然新增一层总负责人，也不是固定的第五角色。它必须与被检对象保持足够的输入、方法或执行路径独立，具体承载方式可以是新 Agent、独立测试进程、人工验收或外部系统规则。

### `root/superagent-boundary-fit/B` 把职责边界组织成交接与独立性关系

- 本层作用：确认边界不是五张孤立的职责说明，而是能在版本、证据、失败和回开中连续传递。
- 输入边界：A 形成的决定对象与授权边界。
- 核心认知动作：建立目标版本、任务版本、产物版本和验证版本之间的引用关系，区分生产、接收、消费、复核和升级。
- 输出边界：下游可直接消费的交接契约，以及监督和验证不被主人公的进度叙事吞没的独立性条件。
- 本层关系：依赖 A；其发现可反馈回 A。
- 放行信号：接收者能读到实际使用的版本、来源和证据，且发生冲突时知道回开哪一层。
- 回开方向：版本失配回开目标或交接边界，验证失配回开验证范围，不得在错误版本下继续细化。
- 后续展开：需要实测消息未送达、负责人失联、产物换版和两个相依工单的组合重验。
- 展开状态：本层已展开

关键关系如下。

- 战略引领者 → 主人公：守恒目标、取舍、成功条件、停止条件和授权版本。主人公可以细化实现，不得静默削弱上层语义。
- 主人公 → 具体做事 Agent：守恒当前任务边界、输入、依赖、完成标准和可修改范围。执行者可以选择方法，不得改变整体目标或范围。
- 具体做事 Agent → 主人公：交付局部产物、依据、版本身份、自检结果和未知。局部通过不能替代组合验收。
- 主人公 → 独立验证能力：提供有效标准、产物、环境和原始输入。主人公可以提出补验问题，不能规定验证者必须得出某个结论。
- 独立验证能力 → 主人公：交付原始证据和通过、失败或未验证结论。主人公在授权内作整体交付判断，不能代替验证能力产生或宣告验证通过结论。
- 监督者 ↔ 全部职责：监督者输出证据性发现、回应状态和升级路径。发现不是目标变更，也不是事实结论的替代品。持续无回应时，监督者将问题交给拥有相应决定权的一方。

### `root/superagent-boundary-fit/C` 把真实任务族映射为适用条件与失配机制

- 本层作用：检查这套职责分配是否把大量不同任务错误压成同一种团队形态。
- 输入边界：A 的职责边界、B 的交接要求、引用对话中的收敛风险和既有工程证据。
- 核心认知动作：区分“职责本身不适合”“启用规模过大”“任务无法被合法分解”“运行保证不足”四类失配。
- 输出边界：任务族、失配机制、受影响边界和最小修正路径。
- 本层关系：依赖 A、B；其结论进入 D。
- 放行信号：每个失配都有具体失败路径和可验证的修正动作，而不是泛泛说“多 Agent 有成本”。
- 回开方向：若一个任务族反复要求同一新增决定对象，回开 A；若边界正确但无法观察或交接，回开 B 或运行层。
- 后续展开：需要在真实任务中测量上下文复制、等待、冲突写入、监督盲区和独立验证收益。
- 展开状态：本层已展开

| 任务族 | 主要失配机制 | 判断 | 最小处理方向 |
| --- | --- | --- | --- |
| 小型、边界稳定、可一次完成的任务 | 角色协商、交接和监督成本超过问题本身 | 不是结构错误，是过度启用 | 主人公单体执行，保留一次轻量自检 |
| 高耦合、共享可变状态、难以隔离的任务 | 多个执行者互相覆盖或共同阻塞，主人公只能事后整合 | 需要先证明可分性，不能由角色名解决 | 单一写入者、顺序化执行或重新设计隔离测试环境 |
| 目标仍在探索、成功条件尚未稳定的研究或设计任务 | 战略与主人公会频繁重写边界，固定任务树制造假确定性 | 结构可用，但必须把假设和回开作为一等状态 | 允许试探性里程碑，战略和主人公保持快速回开通道 |
| 创意、审美和受众反应主导的任务 | 独立验证可以检查约束，却不能仅凭内部标准判断作品是否有效 | 不是验证者失职，是评价来源不同 | 引入真实受众或用户反馈，保留内部验证的范围声明 |
| 持续运行服务和事件响应 | 子事件完成不等于服务结束，战略不应被每个事件唤醒 | 需要服务层与事件层分离 | 运行负责人处理事件，战略管理服务目标、期限和停止条件 |
| 高风险、不可逆、外部授权敏感的任务 | 监督或主人公可能把“发现问题”误当成“有权批准动作” | 结构必须补授权门 | 对每类外部动作绑定决定者、替补、有效期和结果核查 |
| 紧急事故响应和限时处置 | 多层往返会超过响应窗口，普通监督又没有接管权 | 需要紧急模式，不是把普通流程加速 | 预置授权和单一操作负责人，监督旁路记录，验证后置或并行 |
| 长期任务且依赖等待、消息投递或进程存活 | 快照监督无法证明持续观察，失联会产生假阻塞或假完成 | 主要是运行保证不足 | 明确运行层（承载心跳、消息投递和进程状态的系统能力）、观察能力、接替和无替补去向 |
| 高上下文密度、隐私敏感或强连续叙事任务 | 多 Agent 复制上下文造成信息损耗、泄露或观点分裂 | 任务可能不适合拆分 | 单主人公连续处理，只在局部风险足够高时引入独立验证 |
| 医疗、法律、财务、合规等高风险决策 | Agent 没有法定或专业决定权，内部验证不能替代真实签批 | 结构必须补外部决定权 | 引入领域专家或人类最终批准者，缺少签批时只能交付为待决定 |
| 多方利益冲突的谈判和政策取舍 | 单一战略 Agent 无权代表各方，也不能自行折中价值冲突 | 结构缺少真实决定主体 | 保留冲突与来源，交有权的利益相关者决定，Agent 负责方案与影响分析 |
| 需要多个领域共同决策但没有单一授权来源的任务 | 角色边界无法替用户或利益相关者做价值取舍 | 不是再加一个 Agent 就能修复 | 把价值决定交给真实授权者，Agent 只组织方案和影响 |

### `root/superagent-boundary-fit/D` 把失配归因分流为结构修正、条件启用或运行保证

- 本层作用：把 C 的失配转成后续架构能够执行的约束，避免把所有问题都归咎于“监督不够”或“再加一个 Agent”。
- 输入边界：任务族失配机制和现有证据边界。
- 核心认知动作：判断某项缺口是否需要新增决定对象，还是只需选择不同的启用模式、隔离方式、证据机制或外部授权。
- 输出边界：修订后的最小架构和启动前的适用性判定。
- 本层关系：当前层末节点，产出交给下一轮职责协议与 Skill 设计。
- 放行信号：任何角色被启用都能说明启用条件、承担的决定、证据入口和关闭条件；不适合完整分工的任务有明确降级路径。
- 回开方向：若降级路径仍无人负责目标、终止或外部授权，回开 A；若理论边界成立但运行中无法观察，回开 B。
- 后续展开：需要把启用判定进一步展开成可执行粒度，并用任务样本验证误启用和漏启用。
- 展开状态：本层已展开

以下新增载体属于运行或授权承载方式，不是 A-D 的新认知节点。由本层审计得到的最小修正如下。

- 保留“按决定对象分权”的核心，不保留“复杂任务默认开满全部角色”的默认值。
- 把主人公设为有限任务的默认整体负责人，并要求它在派工前判断目标稳定性、任务可分性、外部副作用、评价来源和持续性。
- 战略引领者只在目标、优先级、资源、里程碑或停止条件需要持续判断时独立启用。稳定且边界清晰的任务可以由主人公承接这部分职责。
- 监督者只在持续运行、跨单元组合、高成本失败、不可逆动作或明显对抗性风险下独立启用。进程健康、心跳和消息投递优先由运行层承担。
- 独立验证只在错误代价高、标准可以冻结、且能形成独立证据路径时启用。创意和开放研究应接入受众或领域评审，输出反馈与未知，不伪装成二元通过门。
- 执行者只有在命题、写入范围、依赖和集成点可以隔离时才并行。高耦合任务默认单一写入者或顺序路径。
- 跨多个工作单元时必须显式指定整体集成与交付负责人。多个局部负责人不能自动相加为整体主人公。
- 持续服务、紧急处置、不可逆外部动作和高风险领域需要任务特定的服务负责人、操作负责人、授权门或真实专家决定权。新增这些承载者是因为出现了新的决定对象或外部约束，不是因为角色数量看起来不够。

## 承重边与跨节点义务

#### `A → B`

- 来源语义：每个职责的决定对象、权限、输入和输出。
- 必须守恒：目标、授权、标准、证据责任和事实状态不能因交接改写。
- 下游原生增量：版本引用、接收确认、独立性和回开路径。
- 禁止静默决定：接收者不能因为读取产物就获得生产者的内容决定权，主人公不能因为负责交付就获得独立验证结论的出具权。
- 回开条件：同一版本被不同角色解释，或交接后出现无人负责的终止判断。

#### `B → C`

- 来源语义：交接和独立性要求。
- 必须守恒：适用性测试必须针对真实任务边界与实际证据，不把角色数量当成效果证据。
- 下游原生增量：任务族的并行可分性、评价来源、等待链和外部授权特点。
- 禁止静默决定：不能把某一类任务的运行经验概括为所有任务适用，也不能把“角色已启用”当作“问题已被监督”。
- 回开条件：反例显示缺少新的决定对象，或某个角色在任务族中反复承担不属于原定义的责任。

#### `C → D`

- 来源语义：失配机制及其证据。
- 必须守恒：每个问题只归入结构修正、条件启用或运行保证中的有据类别，保留未知。
- 下游原生增量：最小修正、降级路径、启用门和后续验证计划。
- 禁止静默决定：不能以增加角色掩盖不可分解、无授权或无评价来源的问题。
- 回开条件：最小修正无法使目标、终止或授权有明确承接者。

### 本层跨节点义务

- **收敛义务**：从进入任务起就记录完成条件、停止条件和剩余阻断条件。它首先进入主人公，经过执行、验证和监督，最终由主人公在有效授权内形成有限任务关闭判断。涉及上层目标或真实签批时，回到战略、用户或其他真实授权者。
- **授权义务**：任何改变用户保留目标、成功条件或不可逆外部状态的动作，必须能追到有效决定者和适用版本。监督者只能发现和升级，不能临时补授权。
- **版本与证据义务**：承重产物必须能回查到标准、产物、环境和验证版本。接受记录只证明交接落实，不改变事实或验证结果。
- **独立性义务**：被检对象不能同时成为独立验证结论的唯一生产者和唯一证据筛选者。若不能形成独立路径，输出只能标为自检或未验证。
- **可分性义务**：在启动多个执行者前，必须说明各自拥有的命题、写入范围、依赖和集成点。无法说明时，默认采用单一主人公或顺序化路径。

## 当前层校验结果

- **删除测试**：删除战略引领者后，主人公仍可完成已明确目标下的有限任务，但无法合法改变阶段目标、优先级和上层停止条件。删除主人公后，执行者和监督者没有整体集成与交付责任，终止判断断裂。删除监督者后，短任务仍可完成，长任务和多 Agent 任务失去外部观察。删除独立验证后，低风险任务可自检，高风险和集成任务会失去独立证据。结果支持条件启用，不支持四者固定常驻。
- **空转测试**：仅有角色名称、状态播报或“已接收”不会增加可依赖认知。每个角色必须产生决定、证据、交接或纠偏状态。
- **换序测试**：在目标和可分性未明确前先并行派工会制造返工；在产物未冻结前先做独立验证会造成版本失配；在事实观察前由监督者直接暂停或重规划会越权。
- **桥接测试**：战略输出的是目标与取舍，主人公输入后形成任务网络；执行者输出局部产物，验证者消费对应版本的标准和产物；这些边可连续成立。角色之间不能仅凭“报告”或“完成”两个词桥接。
- **下游被迫补工测试**：若交接缺少标准版本、产物身份和未知，下游必须重建原判断；若独立验证只收到执行者筛选后的摘要，验证者无法独立判断；若主人公只收到局部通过，没有组合验收证据，整体交付仍未闭合。这里的“补工”指下游被迫补做上游本应完成的判断。
- **强反例测试**：共享可变状态、创意受众评价、持续服务、不可逆外部动作和高上下文任务都显示固定四角色结构会误启用、漏授权或制造假独立。结构需要“按条件启用与降级”，不是简单增员。

## 后续展开队列

- `root/superagent-boundary-fit/D`：优先展开“启动前适用性判定”。需要注入任务规模、目标稳定性、可分解边界、外部副作用、评价来源、持续性和等待链信息。若这些信息不足以决定是否并行或是否独立验证，先查现实任务，不直接生成团队。
- `root/superagent-boundary-fit/B`：当任务需要长期运行或真实外部动作时，展开监督、接替、消息状态和授权门。需要注入运行层能力与外部系统权限。
- `root/superagent-boundary-fit/C`：当准备声称“这套结构普遍适用”时，展开跨任务样本验证。需要注入任务族样本、单 Agent 基线、成本、失败率、返工率和独立验收结果。

## 当前未知与失效重开条件

- 当前结论仍是职责和适用性的结构判断，不能推出整体效率、成功率或经济收益。
- 现有工程样题证明了一次有限任务中的交接、独立验收和修复路径可以工作，不能证明角色数量本身带来收益，也不能覆盖长期监督、真实外部服务或高上下文任务。
- 若新证据显示某类任务总需要一个未定义的价值决定者、终止决定者或授权承接者，先回开 A，不能在现有角色下继续堆规则。
- 若边界仍然成立，但运行层无法观测进程、保存版本、确认消息读取或核查外部结果，回开 B 的运行交接，不把运行缺口写成角色职责。
- 若多个执行者反复因共享状态互相覆盖，回开 C 的可分性判断，默认收缩到单一写入者或顺序路径。
- 若用户目标、成功条件或授权发生变化，回开当前根契约，重新确认上层决定权和有效版本。

当前层暂定闭合。后续最值得展开的不是完整 Skill，而是“是否启用战略、监督、独立验证和并行执行”的启动判定，以及它在真实任务样本中的误启用与漏启用结果。
