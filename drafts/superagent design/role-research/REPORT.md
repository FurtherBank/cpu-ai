# 真实源码研究与职责交接验证

本轮继续论证用户提出的多 Agent 职责结构，使用工作区真实 DSH 公开原型作为研究对象。这里交付静态适配判断和实际研究交接证据，整体体系目标继续推进。

## 本轮证据

源码基准为 `8c32a9dc5d72c033816c6a8110b37f40cf94fba4`。两名研究者按命题分别检查接入执行链和监督验证链，独立验证者回查真实源码、反证和报告修订。被列入快照的 207 项文件均匹配，工作区保持干净。本轮未运行原型、测试或外部 Harness。

初始战略约定的六项条件包含五类职责映射、最有利复用途径、适配与失配、独立复核、版本和结论边界。当前依据 “初始战略版本” 与 “第二版冻结记录”；“已接受的发布记录” 说明接受状态、引用位置和消费者确认。

最终研究报告和独立复核结论已在本资料包保留的总报告中摘要呈现。验证者判定 SC-1 至 SC-6 在本轮静态范围达成，同时保留跨 Ticket 整体责任、外部 Harness 和实际运行的未知。

## 对原角色类比的判断

| 用户职责 | 当前原型可承接的部分 | 仍未证明的部分 |
| --- | --- | --- |
| 战略引领者 | 现有事件接入、请求评估、授权与持久任务基础设施可作为适配基础 | 独立阶段判断、受限战略委托、版本化里程碑与再次评估的完整闭环 |
| 军团长 | 每张 Ticket 的 worker 已被要求选择技术方案、验证结果，并拥有子代理工具入口，是较直接的局部候选映射 | 用户整个大型任务若跨多个 Ticket，技术依赖协调、组合验收和整体交付尚无完整承接证明；默认 router 不能只因名称相似就视为已具备这些责任 |
| 监督者 | 健康投影、异常报告、重试、状态补查、提醒与人工入口已有静态机制 | 外部独立 Agent 持续判断业务偏航并形成回应复查的完整实现；主会话的部分观察能力不等于独立实例要求已满足 |
| 执行者 | Ticket/Assignment、worker Session、原始请求、输入和报告有代码连接 | 实际模型的任务拆分、子代理协作和汇总效果 |
| 独立验证者 | 子代理、CI 和 review 可提供执行与证据入口 | 当前报告与结束路径没有要求匹配版本的独立验证回执；真实部署是否另有强制 CI 或分支规则未查 |

这是当前已检视机制下的候选复用途径，没有比较所有方案或度量总成本。它既不能证明必须改掉用户的职责结构，也不能证明原型可以原样承接整套结构。

军团长的责任范围应由待交付的整体任务确定。把一个平台工作单元的负责人叫作军团长，不能自动覆盖多个工作单元组合后的结果；若采用多 Ticket 分解，必须另外明确由哪个军团长实例接收整体目标和相关产物、处理依赖、取得组合验证并作整体交付判断。具体机制仍需适配及运行验证。

## 独立反证改变了哪些判断

验证者提出两项可回查反证，作者保留旧报告并交付 v3 修订。

- **跨模块范围被概括得过宽。** 默认规则允许在既有链路传数据和更新少量调用方，跨模块仍可能属于范围明确的局部工作。打破调用者预期、改变模块职责或多个独立模块协同重设计等条件才触发默认暂停；在原范围内找到可行方法后也可恢复。不能依据文件或模块数量自动上提到战略。
- **消息保留条件被概括得过宽。** 自动 note 是否投递取决于实际的 `liveTicket && automatic && waitsForPerson` 条件。较新的有效人类输入可能已经解除等待，最新报告字面仍为 blocked 不足以证明当前仍需保留消息。note 本身仍不能解除等待，消息送达也不等于问题已经得到回应。

关键源码分别位于 `prompts/team/scope.md:6–18`、`src/core/model.ts:349–352` 和 `src/core/tickets.ts:234–244`。这些结论来自静态回查，相关已有测试本轮只阅读未执行。

此外，独立验证确认任务 ready、PR 关闭或工单结束是生命周期状态，不构成独立质量认证。如果某类任务要求无有效验收就不得交付，需覆盖真实交付入口和匹配版本的证据，不能只修改一句提示词或只检查一个结束分支。

主控还退回了未经比较的“最少改动”措辞，并纠正将本轮只读范围升级为永久新审批要求的表达。后续阶段应核对持续有效的既有授权，仅实际越界时交用户决定。

## 一次实际发生的交接失配

本轮没有为版本交接刻意植入故障。主控在战略 Agent 尚未完成先前压缩要求时提前冻结草稿；生产者随后发现当前文本与冻结指纹不一致。旧冻结记录保留在 “失效的旧冻结记录”，事故记录在 “版本交接事故记录”。

处置保留了不依赖标准版本的源码索引，暂停依赖该版本的结论。生产者明确交付固定副本与指纹后，军团长重新读取并接受，各研究者核对消费版本，独立验证者又回查当前版本身份。原始目标与 brief 保持原文件身份，最终结论依据重新接受的 SC-1 至 SC-6；旧长稿的逐字和完整语义比较仍不在可证明范围内。

旧长稿没有单独保留完整副本，现有记录不能支持逐字比较旧、新全文；关于通知顺序、暂停和历史判断影响的部分是工具消息与角色记录，不是独立观察隐藏推理的证明。本轮可证明当前发布身份和消费记录一致，不能据此宣布长期交接可靠或历史认知完全不受影响。

这个事件促成 v4 规定：生产者明确完成交付，军团长登记落实，消费者确认所用版本；普通草稿文件不直接充当下游的有效标准。接受记录只处理交接状态，目标变更与验证结论仍由各自有权角色决定。

## 对职责协议的更新

`DESIGN-v4.md` 单独保存，不覆盖上一轮 v3。它补充了以下边界。

- 保持目标与成功条件时，军团长可调整方法、组件映射和自己负责的综合判断；改变里程碑或上层承诺才交战略。
- 战略可以依据证据保持原阶段，发现新事实不自动要求一次战略转向。
- 承重产物有固定发布副本、指纹、适用范围和引用位置；接收与消费分别记录。
- 发布或接受的流程状态不改变事实与验证状态，不利报告不能因退回而消失。
- 独立验证结论的修订仍由验证者或有授权的接替者出具，军团长负责交付决定。
- 监督核对最新事件与实际状态条件，并区分记录、送达、读取、回应和复查结束。
- 角色指令、代码校验、工具权限和外部规则分别标明，避免将角色承诺当作已实现保证。

独立冷读发现并复核修复了“接受是否转移内容决定权”和“军团长能否改发验证结论”两项中严重度歧义；过程见 `design-v4-cold-read.md`。这一复核限于文本，不证明运行效果。

## 当前可主张的范围

本轮真实材料研究完成了两条源码链的证据交接、独立反证、修订和版本核对。用户的角色设计已有较精确的规范与具体平台适配边界。当前没有证明完整自主战略、持续语义监督、跨 Ticket 总体交付或强制独立验收已经实现，也没有估计各种任务的适配比例或多 Agent 经济收益。

战略依据本轮真实材料完成复核，保持当前里程碑。下一阶段优先检验两个相依工单在产物换版后，整体负责人能否组织发现、回应、组合重验并作出有据的交付判断；依据和所缺条件已在本段说明。该阶段尚未实施，不能计为本轮运行证据。

阶段关闭记录另存，不由本报告替代军团长的决定。整个体系目标仍进行中。
