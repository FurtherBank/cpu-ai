# T-Imagine：单场景端到端想象推演

接收一个具体场景，把自己放进执行者位置，从当前状态一直推演到交付判定。保留路径中的拟执行动作、预计或直接观测、判断、阻断与换路，不把过程改写成理想计划，也不把想象中的现象冒充真实证据。

## 职责边界

只处理一个用户已明确给出，或能从当前输入唯一整理出的具体任务情境。

- 负责：单场景契约整理、认识状态标记、操作级端到端推演、异常与侧翼路径、交付标准对照。
- 不负责：设计场景集合、比较多份推演、抽象共性、提炼 SOP、替用户完成任务、证明系统实际可用、系统性查清现实事实。
- 默认权限：只模拟拟执行动作；仅在现有授权允许时，只读查证会改变路径的关键前提；除行为日志及写入调用方指定路径或默认路径的推演报告外，不得执行任何写操作，更不得改变被推演任务对象、目标系统或生产环境的状态。
- 制品例外：行为日志和推演报告是本 Skill 的审计与交付制品，允许写入，但必须与被推演对象的写入分开披露；制品写入不证明被推演任务已经执行。
- 路由规则：用户改为要求真实实施或取得通过证据时，停止当前推演，封口并分别返回“转执行”或“转测试”入口，不在本 Skill 内自动继续。若关键结论依赖新增、彼此独立且需要系统搜集或交叉验证的事实材料，或主要交付物将从推演轨迹变成事实结论，同样停止并返回“转研究”入口。

“操作级”不等于“必须有命令”。工程场景可具体到命令、文件和符号；网页场景可具体到页面状态、权限条件和交互入口；写作场景可具体到材料版本、主张、来源、审批状态和决定权。共同标准是：对象可指认、动作可复述、状态变化可观察、下一步有依据。

## 行为日志执行协议

- **规范引用**：[behavior-log/v1 契约](../behavior-log-audit/references/behavior-log-v1-contract.md)；日志骨架：[behavior-log-skeleton.md](../behavior-log-audit/templates/behavior-log-skeleton.md)
- **路径**：`{workspaceRoot}/.skill-logs/t-imagine/yyyy-mm-dd/hhmm-<任务标题slug>.md`。`workspaceRoot` 取当前任务明确声明的工作区根；未声明时取运行时提供的工作区根，再无法取得时取当前工作目录。`<任务标题slug>` 是把任务标题中的空白和路径分隔符转换为连字符后得到的稳定短名；同名路径已存在时依次追加 `-2`、`-3`，不得覆盖旧日志
- **初始化**：首次确认单场景契约之前创建日志，写入元数据、执行边界和状态 `执行中`。任务标题取用户原始任务的最短可辨识短语
- **报告路径**：调用方未指定时，写入 `{workspaceRoot}/.skill-artifacts/t-imagine/yyyy-mm-dd/hhmm-<任务标题slug>-report.md`；沿用日志的工作区、slug 与冲突递增规则
- **增量更新触发点**：
  - 单场景契约判为可推进或待决定时，更新「依据与关键输入」「关键行为」
  - 发生关键只读查证、路径分叉、阻断、侧翼换路或认识状态变化时，更新「关键行为」「偏离、异常与未决事项」
  - 形成报告并完成校验时，更新「结果与验证」「资源索引」，链接推演报告路径
- **子 Skill / Subagent 契约**：本 Skill 不在内部委派 Subagent。被上游作为显式 Skill 调用时，返回 `{推演报告, reportPath, behaviorLogPath, 材料性影响摘要, 分流交接（按条件）}`；上游负责登记子日志
- **封口**：阶段五先校验报告和日志的非终态项；再写入终态、完成时间并封口；最后复核日志结构、空占位与终态一致性。复核失败时修复并再次执行封口后复核
- **与交付物边界**：行为日志只记录推演过程审计，不复制完整推演报告；报告写入调用方指定路径或默认 `.skill-artifacts/t-imagine/` 路径，并把同一内容随当前回复返回

运行时审计标准见 [references/audit-quality-standards.md](references/audit-quality-standards.md)。

## 工作流程

第一步使用可用的任务计划工具创建以下五个阶段，每阶段一项，名称和顺序必须一致。若运行时没有任务计划工具，按同一顺序执行并在行为日志记录该降级。

### 阶段一：锁定单场景契约

**我为什么做这一步**：先固定要推演的唯一、具体任务情境，避免在推演中悄悄生成第二个场景，或用自造条件补齐用户意图。

**Input**：用户原始需求、调用方给出的场景描述及交付要求。

**Goal**：形成一份单场景契约，至少包含背景与目标、约束、当前输入陈述、信息盲区、交付标准；当且仅当能够据此判为“可推进”，或能精确指出导致“待决定”的承重缺口时完成。

**Guidance**：

- 输入已足够具体时，直接整理，不要求用户重复确认。
- 缺少非承重细节时，将其标为推定或未知后继续。
- 缺少交付标准但能从明确目标唯一推出时，写出“暂定交付标准”；若不同标准会改变路径，转为待决定，不替有决定权的人选择。
- 输入实际包含多个场景时，不合并推演；要求调用方选定一个，或逐场景分别调用本 Skill。

契约状态只使用以下两种：

- **可推进**：输入足以开始逐节点推演；未知项可以条件分流，且不会被伪装成唯一事实路径。
- **待决定**：缺失的信息、权限或价值决定使依赖它的关键路径无法推进。待决定也是阶段一的合法完成结果；阶段二只登记该承重缺口和权限边界，阶段三只生成一个“在该缺口处停止”的阻断节点，再进入阶段四形成阻断报告。

**Execution Mode**：主控执行。强依赖用户原始语境，不委派。

**Audit Hook**：更新日志「依据与关键输入」「关键行为」；记录契约状态为可推进或待决定。

### 阶段二：建立推演前提账

**我为什么做这一步**：逼真的细节最容易让预计现象看起来像真实观测。先固定每项认识状态和权限，后续轨迹才能保持客观。

**Input**：阶段一单场景契约；当前可访问材料与工具；调用方授权边界。

**Goal**：形成前提账和执行边界；每项路径前提必须标记为以下一种互斥状态：

- **输入陈述**：在本次 Skill 开始前，用户或调用方已经放入单场景契约的陈述。本次只把“输入这样陈述”作为前提，不表示底层主张为真。
- **直接观测**：本次 Skill 开始后，通过实际只读动作直接看到的输出，并保留动作与来源。只记录观测本身；例如读取文档只能证明“文档写了 X”，不能自动把 X 升格为现实事实。
- **推定**：仅为继续推演而采用的条件化值，不是事实。
- **未知**：尚无证据，且不得被顺手填补。

分类时先写清命题主语：`输入陈述 X` 与 `本次读取到文档写了 X` 是两条不同命题，分别记录；若要判断现实中的 X 是否成立，另建一行，不得用读取文档的动作替它升格。每一行只允许一个状态。

**Guidance**：

- 只读查证仅用于会改变路径的关键前提；查证后将准确描述观测对象的命题标为“直接观测”，记录实际动作、来源和结果，不扩大观测能证明的范围。
- 若关键结论依赖新增、彼此独立且需要系统搜集或交叉验证的事实材料，或主要交付物将变成事实结论，停止扩张，将当前终态记为已分流，并返回“转研究”入口。
- 将所有写操作保留为“拟执行动作”；用户对推演的授权不自动授权真实执行。
- 未知会使下一步不可判定时，在对应节点停止或条件分流，不虚构界面、命令输出、审批意见或成功反馈。

**Execution Mode**：主控执行；可使用只读工具查证。除行为日志及写入调用方指定路径或默认路径的推演报告外，不得执行任何写操作。

**Audit Hook**：更新日志「依据与关键输入」「关键行为」「影响清单」；只读查证须记录来源，未发生被推演对象写入须记录负向边界。若意外写入被推演对象，立即停止，逐项记录对象、动作、结果与处置，终态只能为阻断。

### 阶段三：逐节点推进想象轨迹

**我为什么做这一步**：不先写一份理想步骤表再给它补风险，而是从当前状态逐步前进，让阻断和分支在它们真正发生的位置暴露出来。

**Input**：单场景契约、前提账、权限边界和已经推进到的当前状态。

**Goal**：从接到任务一直推进到交付判定或明确阻断；每个关键节点都形成“当前状态—拟执行动作—观测—判断—下一步”闭环，异常与侧翼路径挂在触发它们的节点上。

**Guidance**：实际执行本阶段前，完整阅读 [workflow/simulate.md](workflow/simulate.md)。只做发现和记录，不提炼跨场景规律、SOP 或统一框架。

**Execution Mode**：主控连续执行。保持同一场景状态，不把不同节点拆给相互不可见的执行者。

**Audit Hook**：在关键分叉、阻断、认识状态变化和侧翼换路时增量更新日志「关键行为」「偏离、异常与未决事项」。

### 阶段四：收束单场景推演报告

**我为什么做这一步**：把连续轨迹压成下游可独立消费的报告，但不丢掉推定、未知和停止条件，也不把单场景材料升格成通用做法。

**Input**：阶段三完整轨迹，或待决定路径生成的单个阻断节点；异常与侧翼路径、当前前提账、单场景交付标准。

**Goal**：按 [templates/simulation-report.md](templates/simulation-report.md) 形成自包含报告并写入稳定路径；逐条对照交付标准，并准确声明目标系统写入、制品写入、只读查证与未完成状态。

**Guidance**：

- 保留对关键结论有影响的节点；压缩重复动作，不删除分支依据。
- 把异常挂回节点后，可在末尾汇总索引，但不得生成脱离轨迹的通用风险清单。
- 终态只使用以下四种：
  - **已推演到交付**：信息足以判断全部交付标准预计满足。
  - **已推演到未交付**：信息足以判断至少一项交付标准预计不满足。
  - **阻断**：关键未知、权限或决定会使不同条件分支落入不同终态，当前无法判断是否交付；阶段一的“待决定”若未解除，必须映射为阻断。
  - **已分流**：用户目标改为真实执行、实际测试或系统研究，或推演已触及对应边界；停止当前 Skill 并形成可消费的分流交接。
- 状态转换：阶段一“待决定”直接进入阻断报告；“可推进”可以进入前三种交付判断终态。推演中新出现的承重缺口使交付判断分叉时，改为阻断。触发路由规则时，无论当前交付判断如何，都改为已分流。非承重未知不改变终态，但必须保留在报告中。
- 阻断必然触发“请求决定或补输入”交接；已分流必然触发对应下一任务交接。两者都必须填写模板的“分流交接”，写清决定者或下一执行者所需输入和重入方式。
- 不得写“实际任务已完成”或“测试已通过”。发生路由分流时，保留已有报告，写明停止原因和下一项任务入口，本 Skill 不自动继续相邻任务。
- 下游可用报告修订计划、设计测试或准备执行，但不得把预计观测当作通过证据。

**Execution Mode**：主控执行；未指定文件路径时，把报告写入默认 `.skill-artifacts/t-imagine/` 路径，并将同一内容随当前回复交付。

**Audit Hook**：更新日志「结果与验证」「资源索引」；报告若落盘，在资源索引记录路径，不复制正文。

### 阶段五：校验报告边界与完整性

**我为什么做这一步**：只检查这份推演是否忠实、完整、可消费，不借校验之名执行真实任务或证明外部系统行为。

**Input**：阶段四报告、单场景契约、前提账与权限边界。

**Goal**：逐项校验并修复失败项；全部通过后才可交付。

**校验清单**：

- [ ] 全文只处理一个场景，未生成场景集合或跨场景结论
- [ ] 输入陈述、直接观测、推定、未知没有混写，所有直接观测项有动作与来源，且未扩大观测能证明的范围
- [ ] 每个关键节点都有动作、观测、判断和下一步；非工程任务也达到可指认、可观察粒度
- [ ] 被推演对象未发生真实写入；若发生意外写入，已标为边界违规并逐项披露，终态为阻断；审计与交付制品写入已单列
- [ ] 每个异常都有触发节点、识别信号、影响和侧翼路径或停止条件
- [ ] 报告逐条对照交付标准，并准确保留未满足项与未知依赖
- [ ] 未提炼 SOP、通用框架或多场景规律，未声称实际任务完成或测试通过
- [ ] 已在行为日志「结果与验证」逐项填写 `标准条目｜通过/失败/不适用｜证据位置｜修复动作`，不得用汇总结论替代

任一项失败，回退到产生缺口的阶段修复。然后对照 [references/audit-quality-standards.md](references/audit-quality-standards.md) 校验除标有 `[封口后复核]` 外的全部条目，在日志「结果与验证」逐项留证；写入终态和完成时间后，再校验所有 `[封口后复核]` 条目，并把结果作为“封口后复核”行追加到同一张留证表。复核失败时，在「更正记录」登记修复，再重新封口和复核。不要新增 behavior-log/v1 固定章节，也不要通过实际执行或测试来补齐推演证据。

**Execution Mode**：主控静态校验。运行时不设置真实行为测试节点；仅在 Skill 开发或改版时，才在隔离环境中用固定输入完整运行一次行为测试。

**Audit Hook**：更新日志「结果与验证」「偏离、异常与未决事项」，随后按行为日志协议封口。

## 返回契约

独立调用时返回完整推演报告。被上游显式调用时额外返回：

- `reportPath`：推演报告的绝对路径；默认把 `{workspaceRoot}/.skill-artifacts/t-imagine/yyyy-mm-dd/hhmm-<任务标题slug>-report.md` 解析为绝对路径，调用方指定路径时也返回其解析后的绝对路径。
- `behaviorLogPath`：本次日志的 workspace-relative 路径，格式为 `.skill-logs/t-imagine/yyyy-mm-dd/hhmm-<任务标题slug>.md`。
- `材料性影响摘要`：一句话分别说明是否做过只读查证、被推演对象是否发生写入、行为日志与报告文件写入了什么、报告处于何种终态。
- `分流交接`（终态为阻断或已分流时）：停止原因、下一任务类型、下一方所需输入或决定、可复用制品、重入方式、明确不得自动执行的动作。
