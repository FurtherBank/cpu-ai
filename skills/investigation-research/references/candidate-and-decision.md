# 候选生成与条件化判断

## 调用契约

- 使用时机：N4X 由模型和证据生成候选；N4 对候选作条件化比较。
- 输入：目标判断、当前模型、明确记录已消费该模型版本的证据账、权限、用户确认的价值/风险条件。
- 输出：候选空间与下一步判断接口。
- 不负责：补做搜索、静默改模型、替用户或专业人员作未授权决定。

## 候选准入

候选必须同时满足：

- 能追回至少一条证据约束的现实关系。
- 说明企图改变的结果及作用路径。
- 证据强度与候选主张相称。
- 适用、不适用和主要风险可表达。
- 不越过当前决定权；专业候选明确标记。

未知只可限制候选，不能作为候选依据。没有符合条件的候选时，输出缺口并回开。

候选空间必须记录自身版本及所消费的契约、模型和证据账版本。候选纳入/排除、来源关系、适用性、权限或覆盖未知改变时升级版本；任一上游版本升级后，旧候选空间自动进入“待重新生成”，不得直接供 N4 使用。

## 候选覆盖未知

候选覆盖未知指当前候选空间可能遗漏的结果、机制或行动方向，以及遗漏如何影响比较。检查：

- 是否只覆盖最常见机制，漏掉指标错误、样本变化或外部因素。
- 是否只比较产品，漏掉流程、行为、暂不行动或先取证。
- 是否只考虑成功路径，漏掉预防、检测、恢复和退出。
- 是否因权限限制删除了专业候选，而非保留并标记。

## 权限状态

| 状态 | Skill 可做什么 |
| --- | --- |
| 用户已授权且属用户决定 | 条件化比较，按已确认价值排序 |
| 组织角色或专业人员决定 | 保留候选、依据和待核实问题，不替其排序或决定 |
| 必须生成具体专业处置才能成立 | 不生成；转为专业评估接口 |
| 权限未知 | 保留分支并请求确认，不能默认授权 |

## 条件化比较

对每项候选回答：

- 它解决什么，不解决什么？
- 在什么条件下成立，什么条件下排除？
- 依据和反证是什么，强度如何？
- 成本、风险、可逆性和信息价值是什么？
- 哪个未知或价值权重会翻转选择？
- 谁有权决定，实施后如何验证？

排序只能消费用户已确认的目标、资源、价值和风险容忍。未确认时给条件分支，不隐含默认权重。

## 判断接口的最小结构

- 判断接口自身版本，以及消费的契约、模型、证据账和候选空间版本。
- 一句话当前判断及范围。
- 当前可依赖的现实模型。
- 候选比较和排除理由。
- 冲突、未知与翻转条件。
- 下一项最高价值信息或有依赖关系的补取任务组。
- 专业/组织核实问题、时效和失效条件。
- 承重主张来源索引。

上游任一版本升级后，旧判断接口自动失效；重新生成或逐条重验并记录继承依据后，才可进入 N5。
