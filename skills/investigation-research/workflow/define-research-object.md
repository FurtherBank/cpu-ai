# 定界理解对象

## Input

- 用户原话、触发调研的现实问题与当前已知。
- 需要理解的对象、相关情境、时间与地域。
- 报告读者、预期理解粒度和后续用途。

## Goal

形成版本化的“研究对象契约”。说白了，它规定本次究竟要把什么讲清楚、讲到多深、哪些内容不属于本次调查，而不是提前规定最后该选什么。

契约至少包含：

- 原始问题与触发原因。
- 研究对象、范围、近敌和明确排除项。
- 相关情境、时间、地域、版本与目标读者。
- 用户已知、关键未知和希望理解到的粒度。
- 六层完成要求：对象骨架、范围内基线、关键分化情境、差异/争议/边界、规律性特征、未知。
- 后续用途边界：只影响解释粒度，不授权本 Skill 生成或裁决方案。
- 紧急性、隐私、访问权限和专业表达边界。

## Guidance

- 把“哪个好、该不该做、怎么解决”改写成可调查的理解问题，例如：材料中已经存在哪些做法、各自如何定义和实施、材料报告了哪些结果、结果在什么条件下不同、有哪些争议与未知。允许按中性可观察轴描述性对照这些既有对象；不得作总体优劣评价或为选择服务的筛选、排序和推荐。
- 不把用户预设当作事实；将其记录为输入陈述或待查问题。
- 只在对象、范围、危险性或完成标准无法安全推定时补问。能通过第一轮材料校准的内容先暂定版本，不把追问当进度。
- 若对象包含多个不可共享骨架的子对象，拆成独立研究对象；若只是同一对象的不同情境，保留为同一契约中的情境分支。
- “某软件为何故障”缺仓库/版本/症状定义、“某城市当前情况”缺城市/时间/制度范围，或“大模型记忆”未区分参数记忆/上下文记忆/外部记忆时，不得擅自补成方便研究的对象；先取得承重身份或拆分对象。
- 若用户要求本 Skill 直接推荐、排序或确认个体适用性，明确分流：本次先交付研究全貌，决定由用户或有相应职责的后续流程完成。

## Execution Mode

主控执行。不得在本阶段搜索、生成方案或下应用结论。

## Static Check

- 裸读者能回答“谁需要理解什么、在什么范围和粒度内、为何要理解”。
- 每个边界都能影响搜索、归纳或叙事，而非空泛标签。
- 完成条件检验的是理解全貌，不是能否得出某个选择。
