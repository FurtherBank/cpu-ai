# refbase-edit

引导 agent 维护 **依据库**（与 `refbase` README / AGENTS 中的「资料区」同指）：在固定目录写入 Markdown，使 `rb <索引>` 打印出正确内容。

## 术语速览

| 术语 | 含义 |
| --- | --- |
| 依据库 / 资料区 | 同一物理目录：`~/refbase-workspace/data`（可用 `REFBASE_DATA_DIR` 临时覆盖，测试用） |
| 索引 | 文件名去掉一层 `.md` 后的名字（也称 stem）；`rb` 参数只接受索引，禁止含 `/` 或 `\` |
| runtime 变体 | 同基名下的 `<索引>.codex.md` / `<索引>.cursor.md`；有对应 Agent runtime 时优先于共享 `<索引>.md` |
| 扫描首个 | 全树按目录名 `zh-Hans-CN` 排序后做深度优先遍历，同名文件取第一个命中 |

## 职责边界

**本 Skill 拥有**

- 决定落盘相对路径、索引名、是否写 runtime 变体
- 新建前 / 改名前全树查重；禁止静默覆盖已存在的同名文件
- 执行写入、就地编辑、显式改名（含搬齐变体）
- 用 `rb <索引>` 做读取侧验收

**本 Skill 不拥有**

- 条目正文的生产方法论（概念升维用 `t-concept-refactor`；或直接使用用户已给出的正文）
- `refbase` 仓库内的 `rb` CLI 改动、npm 发布、本机命令激活（如 `ccli activate`；见仓库 `AGENTS.md`）
- 单方面裁定并创建新的顶层分类体系（可建议，须用户确认后再建）

**禁止**

- 把依据库文件写进 `refbase` git 仓库或准备 `npm publish` 的包路径
- 把路径写进 `rb` 索引（如 `rb concepts/foo`）
- 不按下方「读取契约」的命中规则定位就改文件（会改错 runtime 变体或非实际命中文件）
- 为「命名整齐」擅自改已有索引（除非用户显式要求改名或为消碰撞）

## 读取契约（写入前必懂）

```bash
rb <索引>          # 只打印命中文件全文；不打印路径；未找到则非 0 退出
```

解析要点：

1. 索引 = 文件名去掉一层 `.md`；`foo` 与 `foo.md` 等价
2. 子目录只做分类，不进入索引字符串
3. 有 runtime 时候选顺序：`<索引>.<runtime>.md` → `<索引>.md`；无 runtime 只认共享 `.md`
4. 某 runtime **不会**读取另一 runtime 的专属文件
5. 权威数据根：`~/refbase-workspace/data`（不是仓库内软链；软链仅供编辑器浏览）

**定位真实文件路径**：`rb` 不输出路径。需要路径时，在数据根下按候选文件名（`<索引>.<runtime>.md`、`<索引>.md`）做全树查找；编辑器若已建立软链，可浏览 `refbase/workspace/data/...`，但写入目标仍须是数据根下的真实文件。

## 命名与放置

### 新建默认路径

下列为常用默认目录，不是唯一允许目录：

| 条目类型 | 默认目录 |
| --- | --- |
| 概念对照 | `~/refbase-workspace/data/concepts/` |
| 项目依据 | `~/refbase-workspace/data/project/` |

二者都不贴切时，可建议新的顶层英文短目录，**用户确认后再创建**。默认不把条目直接落在 `data/` 根下。

### 新建索引命名

- **概念对照**：`{概念1}-vs-{概念2}[-vs-{概念N}...].md`（优先 `-vs-`，新建不用 `、`）
- **项目依据**：ASCII slug，如 `cpu-cli-tool.md`
- 文件名须覆盖条目要对照的全部核心概念；标题可以更口语，但新建时标题不得额外引入文件名里没有的核心对照概念。说白了：索引里写了谁，标题就不能再多塞一个「正式出场」的概念。
- 中文文件名合法，概念条目以中文为主

### 编辑已有

- 默认只改正文，不改路径 / 文件名 / 索引
- 历史例外保留：如 `信任、依赖、信赖.md`（顿号）、文件名所含概念少于标题所含概念的旧条目——不自动「纠正」改名

### runtime 变体

- **默认只写共享** `<索引>.md`
- 仅当正文必须因 Codex / Cursor 分叉时，才叠加 `<索引>.codex.md` / `<索引>.cursor.md`；`rb` 参数仍只用 `<索引>`
- 若只建专属文件、不建共享 `.md`：无对应 runtime 时 `rb` 会「未找到」——仅在刻意 runtime 独占时允许，且须向用户说明

## 查重（新建与改名前必做）

在数据根下查找任意深度的：

- `<索引>.md`
- `<索引>.codex.md`
- `<索引>.cursor.md`

或先执行 `rb <索引>`：

- **已命中** → 禁止静默另建同名；改为编辑已命中文件，或更换索引名
- **未命中** → 可按放置规则新建

同名全树取扫描首个。若跳过查重、或未消除同名碰撞就另建文件，以后 `rb` 可能读到「不是你以为的那份」。

注意：只换子目录、不换索引名，消不掉同名碰撞。

## 工作流

先判定模式，再只走对应分支。

### 新建

1. 确认正文来源：用户已给正文，或先完成上游写作（概念对照可先走 `t-concept-refactor`），再入库
2. 选定类型 → 默认目录；目录不存在则 `mkdir -p`
3. 拟定索引名（无 `/` `\`）→ **查重**
4. 默认写入 `<目录>/<索引>.md`；仅在必须分叉时写 runtime 变体
5. 验收：`rb <索引>`，确认输出为刚写入内容的开头与关键段落
6. 向用户回报：索引名、绝对路径、验收命令

### 编辑

1. 用 `rb <索引>` 读出当前 runtime 实际命中的内容
2. 在数据根按读取契约的候选文件名全树定位真实路径；确认要改的是这份命中文件，还是某一 runtime 专属变体
3. 就地改文件；默认不改名
4. 再跑 `rb <索引>` 验收

### 改名（仅用户显式要求或为消碰撞）

1. 新索引名合法且 **查重通过**
2. 搬迁同基名的 `.md` / `.codex.md` / `.cursor.md`（有则全搬）
3. `rb <新索引>` 应命中；`rb <旧索引>` 应失败
4. 回报新旧索引与涉及路径

## 与上游交接

| 情况 | 动作 |
| --- | --- |
| 用户只要入库、正文已有 | 直接走本 Skill 新建/编辑 |
| 用户要「升维 / 形式化区分概念」且尚无合格正文 | 先 `t-concept-refactor`（或等价产出），再本 Skill 落盘 |
| 用户要改 `rb` 命令行为本身 | 不走本 Skill；转到 `refbase` 仓库研发流程 |

## 完成自检

- [ ] 文件在 `~/refbase-workspace/data`（或当前 `REFBASE_DATA_DIR`）下，未写入 git 包路径
- [ ] 索引无路径分隔符；新建概念对照使用 `-vs-`
- [ ] 已做全树查重；无静默同名覆盖
- [ ] 未擅自改已有索引；改名时变体已搬齐
- [ ] 默认共享 `.md`；专属变体仅在有分叉理由时存在
- [ ] `rb <索引>` 验收通过，并已向用户给出索引与路径

## 微型示例

用户：「把『耐心 vs 忍耐』的分析报告放进依据库。」

1. 正文已就绪 → 索引 `耐心-vs-忍耐`，目录 `concepts/`
2. `rb 耐心-vs-忍耐` 未命中 → 写入 `~/refbase-workspace/data/concepts/耐心-vs-忍耐.md`
3. `rb 耐心-vs-忍耐` 打印成功 → 回报索引 `耐心-vs-忍耐`
