# 任务与消费验证基线

## 输入与目标

输入：用户需求、原始材料、已有产物及维护约定（如有）。本阶段要明确本次整理为谁解决什么问题，以及什么现象能证明已经解决。

## 执行

1. 确定范围、目标读者和消费动作。把“方便使用”改成具体任务，例如“查当前上线日期和依据”“按条件选择处理分支”“判断某主张在哪些条件下成立”。
2. 选择一次性重构或持续维护，并选择轻量、标准或审计强度。记录理由；用户只要静态文章时，不附加知识库运营任务。
3. 确认输入完整性。记录文件、会话、版本、可定位段落及缺失部分；拿到预览不能当成拿到全文。易变材料在权限允许时保留快照或版本标识，无法保全时记录风险。
4. 写出不可改变的业务要求、事实表达边界、隐私范围和输出要求。用户已授权设计变更时，另记授权范围，不冒充来源事实。
5. 选择足以覆盖主要消费路径的具体任务作为验证基线：主路径，以及会改变判断的重要例外或“证据不足”路径。小任务一两个即可，复杂任务按关键分支增加，不靠数量凑齐。
6. 在原材料或旧产物上实际试做，记录入口、卡点、需要回看哪些材料、能否得到有依据的结果。原状态无法测试时说明原因，不虚构对照结果。持续维护另选代表性变化供阶段六演练。

涉及正式操作的 SOP 可以验证信息路径和分支判断；未经授权不代用户执行外部操作。注明验证止于哪一步，不能因此宣称现实执行已成功。

## 产出

一份简短任务说明，至少包含：

- 输入范围及缺口、不可改变约束、执行路径与强度。
- 目标读者、目标任务、产物形态和保存位置。
- 消费验证基线：任务、原结构卡点、通过条件、依据位置。
- 持续维护时：已有信息模型位置、待接入材料范围、代表性变化；未知项明确标注。

目标不清但可继续时，使用有依据的暂定消费任务并标明假设；影响范围或关键取舍且无法从材料推定时，向用户澄清，同时推进独立工作。不得把自选目标说成用户已确认。
