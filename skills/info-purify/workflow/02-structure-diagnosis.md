# 结构诊断与模型选择

## 输入与目标

输入阶段一的任务与验证基线、代表性原始材料、已有结构。目标是解释卡点的成因，并选出能解决它的表示方式。

## 执行

1. 沿消费任务定位障碍，关联到具体材料。例如“查当前状态要逐条读历史”“同名项目混在一起”“结论没有条件”“一个事实在三个视图独立维护”。不要只写“层级混乱”。
2. 从代表性材料识别反复出现的对象、主张、关系、状态或约束。对象身份、关键时间、已暴露冲突从此时就处理，不等到最后补台账。暂时不需要全量逐句编码。
3. 提出能解决障碍的信息模型，以及由它生成的消费视图。目录只是视图的一种，不把章节顺序当成模型本身。
4. 重要结构有不同可行方案时，比较其任务覆盖、语义保真、额外维护成本与新材料适配。比如按时间读历史与按对象查当前状态可以并存，共享依据，不必二选一。
5. 用一个难归类或反向材料挑战候选：是否需要硬塞进“其他”？是否抹掉条件才放得下？是否新增一条就要增加一个类别？若是，修正表示或保留未决边界。
6. 判定哪些障碍可通过信息组织解决，哪些需要查证、专项判断或现实规则变更。后者登记交接或升级候选，不把整个重构任务都退回为问题清单。

## 产出与退出条件

记录“障碍—证据—影响任务—候选结构—选择理由”，附必要的反例和保留/改造范围。无需强制表格。

每项新增模型元素应能指出服务哪个任务或保留哪个关键区别。原结构已经满足要求时，允许选择保留，并给验证依据；不能为了证明做过工作而强改结构。

持续维护任务要能初步解释：典型新增材料会落到哪些已有对象、关系或主张；什么情况需要模型演化。不能解释则进入阶段三继续试建，不宣布结构已经稳定。
