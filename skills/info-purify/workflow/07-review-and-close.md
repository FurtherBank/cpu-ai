# 独立复核与交付收束

## 输入

用户需求、阶段一任务与不可改约束、产物本体、信息模型与维护说明（适用时）、净化日志记录、原始材料及可定位来源。本阶段必须让复核者能查看原始材料，不能只拿主控自己的总结互相证明。

## 委派方式

有可用 Subagent 时委派只读独立复核；不绑定 Task 等特定工具名。使用新的、不继承主控推导过程的上下文，只提供执行所需材料、目标任务和以下标准，不提供“应该通过”的暗示。复核者不补写正式正文、不修改来源、不替业务做新决定。

没有 Subagent 时主控按同一标准执行，交付写明“未进行独立复核”。拿不到关键原始材料时明确标为无法独立验证的范围，不能报告全项通过。

派发内容应包含：

> 请只读复核这次信息净化交付。先独立从产物入口完成给定消费任务，再核对来源、模型、映射与测试记录。持续维护场景还要检查更新规则能否处理给定变化。不要依赖主控结论，不要补写正文；先返回失败和风险，再给通过项。每项指出位置、依据、影响任务、严重度和建议回退阶段。
>
> 用户需求及不可改约束：提供原文或可读取路径。
>
> 目标读者与消费任务：提供阶段一记录。
>
> 产物、来源、模型与日志：提供可读取路径。
>
> 复核标准：本文件。
>
> 允许操作：只读；若需执行更新演练，仅在明确指定的临时副本中进行，不修改正式产物。

## 复核标准

| 检查 | 需要看到的证据 |
| --- | --- |
| 任务匹配 | 目标消费任务实际可完成，所需产物齐全，未偷偷缩小任务 |
| 结构理由 | 原卡点与模型、视图选择有联系；保留旧结构或改变结构均有依据 |
| 表示适度 | 身份与概念边界够用，关系有含义与依据，没有为填表臆造现实规则 |
| 语义保真 | 关键条件、例外、异议、状态和未知未被抹去；源到结果与结果到源可对照 |
| 依据适用 | 来源能支持对应主张，权威、时间、范围不混淆，缺失核验明确标注 |
| 实际可用 | 复核者只从产物入口也能找到答案或正确停止，不依赖日志补隐藏前提 |
| 持续维护 | 适用时模型、依赖和规则可定位；更新测试有实际结果，旧结论不残留 |
| 交接边界 | 通用处理与专项待决分开；升级候选未伪装成既定结论 |
| 证据限度 | 未测试不说通过，合成演练不说长期实证，阻断问题不被风险清单“放行” |

审计模式对关键事实、规则和冲突逐项核查；其他材料可按风险抽查，报告覆盖范围。后置核查不能替代建模时对身份、来源和关键关系的判断。

## 修正与收束

主控处理失败项，更新受影响的模型、映射、正文和日志，并重跑相关验证。高、中严重度失败须修正后让复核者重新核验；确实无法修正的，明确受阻任务，降低交付状态，不宣称通过。

最终交付状态：

- **通过**：约定任务及必要验证完成，无阻断失败。
- **限定范围可用**：核心任务已满足且有验证证据，但部分非核心范围受阻或未验证；列清可用范围、限制、理由和下一步。不能同时宣称整体可用。
- **未通过**：核心任务仍受阻，或核心任务缺乏足以判断通过的证据。此项优先于“限定范围可用”；可另列已可用的辅助内容，并交付当前草案和问题交接，但不叫完成品。

复核记录先列失败、风险和未验证范围，再列通过证据及修正结果。最终回复说明产物入口、主要改善、验证结论和剩余限制；无需倾倒全部工作记录。
