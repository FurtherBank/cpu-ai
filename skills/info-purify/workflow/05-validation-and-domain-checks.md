# 语义核查与专项交接

## 输入与目标

输入信息模型、产物草案、来源与映射、消费任务及正式领域依据（如有）。本阶段集中核验前面持续进行的语义判断，而非等到此时才第一次看冲突。

## 核查动作

- **事实与状态**：逐项核对关键事实和执行要求。区分来源声称、已核实、推断、假设、候选和未决；再看当前、历史或已失效。以范围、有效时间和适用权威判断，不按“最新消息胜出”覆盖。
- **概念与身份**：核对同名异物、异名同物、范围和易混概念。缺字段时先判断任务是否需要；需要但未知就标未知，不编造生产方或维护方。
- **依据与权限**：对具体主张说明来源为何适用。规范、观察记录、个人建议各能证明什么；维护者有资格修改什么。没有统一优先级时不得自造权威排序。
- **关系**：核对关系两端、方向、条件和依据，特别是依赖、支持、反驳、替代、前后置与约束。相关性不自动等于因果。
- **领域风险**：按实际材料选择检查项；未知类型先从消费任务推出临时检查项，写明其依据和非权威性质。需要现行外部标准时查证，无法取得时标出具体受阻结论，不凭记忆补正式要求。

## 按需选用的领域检查

| 材料 | 重点 |
| --- | --- |
| 规则、规范、SOP | 适用范围、触发、分支、完成条件、异常和执行主体；当前要求与历史/候选分开 |
| 架构或契约 | 事实、约束与方案分开；模块关系、字段语义、必填性、生产消费方、兼容范围 |
| 会议、聊天 | 决定与建议分开；行动项的责任人和期限是否有来源；异议及情绪的含义不被抹去 |
| 研究或知识文章 | 主张的适用条件、证据和反例；跨文档重复、冲突、断链；不能把观点清单当成论证 |
| 持续知识库 | 失效、替代和待复核是否传播到相关视图；已有生命周期政策可执行，新增淘汰政策或组织责任另行交接 |

## 未决项怎样处理

先完成当前权限和材料足以支持的查证与修正，不把可以处理的问题一律交给用户。

- **补充信息请求**：缺哪份证据、影响哪项判断、去哪获取。
- **专项审查交接**：需要什么领域判断、为何超出已做核查、应由哪个角色判断、当前能用什么。没有已知接收者就写“待指定”，不能虚构责任人。
- **升级候选**：需要新定什么规则、设计或权责，现有材料为何不能决定，哪些任务受阻，现有授权是否覆盖。

三类记录可以共用一张表，但用类型字段分开；无条目时写“未发现”。“已处理的通用问题”和“仍待专项判断的问题”必须可区分。

## 回退与退出条件

核查推翻了对象身份、概念边界或关键关系，回阶段二、三重做模型，并更新阶段四映射；来源更正则回阶段四，沿依赖更新。将受影响视图和测试标为待复查，不能保留旧的通过结论。

输出核查结果、失败或未决项、处理路径和可用范围。阻断核心任务的问题未解决，可以交接整理成果，但不能宣布核心任务已经可用。
