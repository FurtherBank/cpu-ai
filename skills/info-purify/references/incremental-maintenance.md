# 增量维护规则

本文件仅供持续维护路径使用，阶段三设计规则、阶段四处理实际变化、阶段六验证。规则可以由人或 Agent 执行，不暗示已经建成自动化服务。

## 更新前要具备什么

必须能找到当前信息模型、当前记录、原始来源、视图依赖和上次有效版本。这些可存在同一文档或既有知识库中。所谓视图依赖，就是知道“一条依据改了，哪些正文、问答、示例或汇总要一起检查”。

若旧体系没有这些信息，先在本次范围内补建。不能把未知影响范围说成“只需改这一段”；无法界定时扩大查找和复核范围，必要时退回首次重构路径。

## 一次更新怎样做

1. **接收与定位**：保留原始来源及本次收录位置，确认涉及的对象、范围、版本及必要的有效时间。名称不唯一时保留歧义；迟到历史材料不能按收录时间成为当前状态。
2. **辨别变化**：用下表选择动作；一段材料可能包含多种变化，先拆开处理。根据内容和来源定位去重，不能仅靠措辞不同就认作新事实。
3. **计算影响**：沿“来源 → 主张或规则 → 关系或推论 → 消费视图”查找受影响位置，包括依赖结论的示例、摘要和操作说明。身份合并、拆分或全局约束变化可能影响全局。
4. **准备可恢复的修改**：保存上个有效版本或差异记录；在副本或可撤销编辑中完成本次记录及关联视图的更新。未完成同步时，正式交付不得宣称已更新完成；确需保留中间状态时显式标为待复查。
5. **验证与接纳**：运行受影响的消费任务，核对来源、历史和视图，检查重复接入不会新增重复记录。通过后保存为当前版本；失败则修复或恢复上个有效版本，并记录未处理材料，不能丢弃变化输入。

“计算影响”可以是人工沿链接检查，不要求程序化依赖图。小型材料可检查全部视图；大型材料应有可定位的依赖记录，以免每次全量重读。

## 变化类型与动作

| 类型 | 如何判断 | 动作 |
| --- | --- | --- |
| 重复或转述 | 同一对象、范围、时间、主张已存在 | 复用记录，必要时补来源；同源转载不增加独立证据数量 |
| 新实例或新主张 | 现有模型能表达的新内容 | 新建对应记录，接入相关视图，不随意加类别 |
| 属性或证据补充 | 不否定现有内容，新增细节或独立支持 | 补充记录及支持关系，保留适用条件 |
| 现实状态变化 | 同一对象在不同有效时间发生改变 | 更新相应时间范围内的状态，保留事件历史；不称旧事实为错误 |
| 更正 | 有适用依据说明旧记录错误或现有表达误述来源 | 关联旧记录与更正依据，更新结论和依赖视图；不改写原始历史 |
| 撤回或失效 | 明确撤回来源、废止规则，或触发已有失效条件 | 标记相应依据/规则失效，重新评估依赖结论；失去证据不自动等于反命题为真 |
| 冲突 | 同对象、同范围、重叠时间的说法不相容，且没有足够裁定依据 | 并列保留主张、依据和受阻任务，进入待确认；不能静默覆盖 |
| 无法归入 | 身份不明、范围外、关键例外或模型缺少必要表达 | 先区分原因；保留待确认/范围外记录，或启动下节模型演化 |

新版本已正式生效时，可根据其授权和适用范围更新现行记录；未生效版本保留将来适用时间。若批准状态未知，不能把“新版本”直接当作正式替代。

## 信息模型什么时候演化

模型演化只改变如何表达已知信息。比如同一项目不同地区有不同状态，原来的单一状态字段不足，需要增加地区范围。它不授权修改项目的实际批准流程。

以下信号触发重新判断：

- 目标任务依赖一个模型尚未表达的区别。
- 同类有效材料反复无法归位，或不断增加临时例外。
- 身份规则导致误合并/误拆分，已有关系无法正确表达新材料。
- 用户的消费任务或信息范围发生实质变化。

先排除来源错误、身份歧义和范围外材料，再比较：补充字段、拆分概念、增加关系，还是需要整体重构。不要每遇新实例就增加分类，也不要为了保持模型不变删除例外。

选定变化后保存模型版本或变化说明，写出旧记录到新记录的映射，迁移受影响内容，更新视图和使用说明。检查旧链接或引用是否仍指向正确对象；跑相关消费任务和一个迁移案例。迁移失败时恢复上个有效版本或明确限制可用范围。无须对完全无关记录做形式化重写。

如果必要变化会新定现实权利、义务、执行条件或契约，则进入升级候选；可继续整理不依赖该决定的部分。

## 最小维护交付

只需留下足以让下一次执行的材料：模型及当前记录的位置、来源与依赖定位、本次变化和依据、历史/失效去向、验证结果、未决项和恢复办法。可以是一份文档的几个段落，不强制另建系统。

维护演练验证的是已测试的变化类型，不保证未来所有变化都能局部更新。依赖全局或模型发生变化时，全量复核可能是正确选择。
