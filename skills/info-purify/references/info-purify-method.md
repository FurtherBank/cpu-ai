# 信息净化方法

## 目标与实现原理

信息有序化要降低的是特定使用任务中的负担：读者少翻原文，少猜概念和状态，维护者少找重复副本。它不以分类层数或压缩字数为目标。

实现上有两种互相校正的动作：

- 从使用任务出发，设计应该怎样查找、阅读和判断。
- 从原始材料出发，识别真正存在的对象、概念、关系、条件和例外。

前者决定视图，后者约束表示。只有自上而下设计目录，容易把材料硬塞进去；只有自下而上建台账，容易有记录却没有可用结构。因此先有足够的来源定位和代表性材料，再提出模型草案，用全量整合与反例修正，最后实际使用。

## 理论启发及其适用限度

本方法受到对话[信息有序化思路](chatgpt-conversation://6aec3ed9-b2bc-83ec-9e9c-436932d1315e)启发。该对话主张从增长信息中识别稳定抽象，并建立融入、更正及扩展规则。以下是对理论的工程借鉴，不是它们对本 Skill 效果的数学证明。

| 来源 | 支持的原意 | 本 Skill 的设计推导 | 不能据此声称什么 |
| --- | --- | --- | --- |
| Rissanen，[Modeling by shortest data description](https://www.sciencedirect.com/science/article/pii/0005109878900055)，1978 | 模型选择同时考虑模型及数据的描述成本 | 比较表示规则的复杂度与剩余重复、例外的处理成本 | 字数越少越好；已计算实际最小描述长度 |
| Tishby、Pereira、Bialek，[The information bottleneck method](https://arxiv.org/abs/physics/0004057) | 在压缩表示时保留与目标变量有关的信息 | 先定义消费任务，再决定哪些内容进入哪个视图 | 已估计互信息；可以删去未知用途的原始材料 |
| Codd，[A relational model of data for large shared data banks](https://doi.org/10.1145/362384.362685)，1970 | 用关系表示数据，减少使用对内部组织方式的依赖 | 把对象身份、事实及关系与文档位置分开，使一份依据支持多种查询 | 必须使用数据库；对象—属性—关系是该论文给出的通用写作公式 |
| Gupta、Mumick，[Maintenance of Materialized Views](https://homepages.inf.ed.ac.uk/wenfei/qsx/reading/gupta95maintenance.pdf)，1995 | 根据基础数据变化维护派生视图，部分场景可避免全量重算 | 保存依据到结论、结论到视图的依赖，变化后更新受影响范围 | 任意自然语言变化都能局部处理；有全局依赖时仍只改一处 |

“模型更简单、查询更直接、更新更局部”是待验证的工程目标。不能给自然语言材料编造一个熵分数来证明已经完成。

## 怎样选足够的模型

**信息模型**是对这批材料“描述什么、怎样区分、怎样关联”的表示约定。说白了，它决定遇到一条新信息时，应当认出什么，而不是先决定该塞进哪个文件夹。

例如：

- 项目记录：项目身份、负责人、计划和实际状态、改变它们的事件。
- 研究材料：主张、适用条件、证据、反例、仍待回答的问题。
- 规则体系：适用对象、触发条件、要求、例外、依据与有效范围。
- 单篇文章：关键概念和论证关系通常已够用，不必建立对象表或事件库。

模型来自材料里可观察的规律，也来自读者要完成的任务。材料没有提供的现实规则不能因模型需要而补造。候选模型要用难归类材料、同名异物、关键例外检验；无法表达时修正模型或保留未决项。

比较候选时看四件事：目标任务能否完成；关键区别是否保留；多少重复与例外要额外维护；下一类代表性材料能否接入。优先选满足任务的较小模型。没有实质性替代方案时不强制凑多个。

## 表示、依据与视图

原始材料提供证据，不直接决定当前结论。信息模型规定身份与关系；模型中的记录表达已知、声称、推断或待决内容；消费视图按任务选择并呈现这些内容。

例如“项目 A 当前计划周一上线”可以被项目视图和负责人视图同时使用。两处指向同一记录或写明依赖，不各自决定日期。正式变更已生效时更新当前计划，保留“原计划周五”；只有建议变更时保留现行计划，并并列建议。

这些是逻辑职责，不要求拆成四套文件。一个 Markdown 文件也可以承载它们。需要稳定寻址时用已有标题、记录号或链接；不要为了形式增加无用 ID。

## 语义与时间的最小区分

- **内容类型**：事实陈述、规则、推断、假设、建议、问题等。
- **证据状态**：已核实、仅来源声称、存在冲突或待确认。
- **时间状态**：当前适用、历史记录、已撤回或失效。

三者不能揉成一个含糊的“状态”。例如旧版规则可以有可靠来源，但已不适用于新版本；最近收到的建议仍不是现行规则。只保存本任务需要的维度，未知时间写未知，不由消息顺序臆测。

时间会影响结论时，区分事件发生或规则生效的时间，与本次收录时间。不同版本、地区或对象下同时成立的说法，不一定冲突。

置信度如有使用，写理由；不能用“高置信”代替来源，也不能用单一排序决定所有来源的优先级。规范说明应当怎样，日志说明观察到什么，二者不一致可能是执行偏差，不能直接互相覆盖。

## 改造动作与边界

| 动作 | 使用条件 | 必须留下什么 |
| --- | --- | --- |
| 保留、移动、上提、下沉 | 改善消费顺序，或原位置已合适 | 理由与去向 |
| 拆分 | 同一段包含可独立判断的主张、状态或条件 | 各部分的关联和共同上下文 |
| 合并 | 对象、范围、时间和含义确实等价 | 原来源和独有条件；重复出现不代表多份独立证据 |
| 隔离、排除出正文 | 历史、候选或无关内容不应进入当前主线 | 仍可寻址的原文及排除理由 |
| 更正、标记失效 | 有适用的更正或撤回依据 | 新旧对应、依据、受影响位置 |
| 信息模型演化 | 现有表示装不下关键区别 | 模型变化、迁移映射、复查范围 |
| 升级候选 | 需要另行决定现实规则或设计取舍 | 触发材料、受阻任务、待决定内容与交接对象 |

信息表达错误能依据来源修复时应修复，不一律升级。新证据不足以裁定争议时，并列保存争议与适用范围，暂停依赖争议结论的任务。表示完成与现实问题解决是两回事。

## 用什么证据判断改善

消费验证：从真实问题进入产物，找依据、辨条件、得出判断或执行到约定终点。记录使用了哪些入口和是否仍要重读原文；与原结构中记录的卡点比较。不要编造阅读时间或未经实际测量的效率数字。

维护验证：对持续维护任务，试一次代表性新增，再试适用的更正、撤回、乱序或结构例外；检查新旧结论、历史、相关视图和未受影响内容。未在真实长期运行中观察的效果，只能称为演练通过。
