# 封口体系关系

## Input

- 通过节点闸门的节点账。
- 节点引用的承重主张。
- 认知契约中的主要变体和不可牺牲约束。

## Goal

在 `system-map.md` 加入关系词典、边表和真实/待核验循环记录。边字段遵守 [产物契约](../references/artifact-contracts.md)。

当每条承重边可说明方向、条件、失效后果和主张支持，认知基座有删除反事实，伪循环与真实循环已区分时完成。

## Guidance

先按 [六类关系正定义](../references/artifact-contracts.md#边字段) 写完整句 `read_as`，再选关系类型。写不出“源变化为什么影响目标”时不画边。只有缺失源会使目标含义、正确性或可判断性失效时，才标理解前置；仅有帮助的关系留给路线建议。

认知基座由关系产生：删除节点后，多项终态能力，或至少两个互不从属的下游理解前置分支失去合法结构支撑，且这种作用跨主要变体稳定，才标 `structural_role=foundation`。证据只引用受阻能力、节点和边，不引用阶段五才生成的路线；路线复用只能触发复核，不能补做判定。

循环按以下顺序核验：

1. 拆过大节点。
2. 消歧术语。
3. 校正时间尺度和对象边界。
4. 寻找共同前提。
5. 对剩余闭环逐边删除反事实。
6. 用案例或条件正反向定位。

证据不足的闭环标 provisional 或待核验，不为路线便利强拆成 DAG。横切约束也必须是一次认知变化，并只保留单一节点，以条件约束边连接受影响节点。例如 `N-PERM 判断操作者权限边界` 同时限制导出与退款，只保留该节点，再建立 `N-PERM → N-EXPORT`、`N-PERM → N-REFUND` 两条条件约束边；路线在首次形成行动判断前经过它，不复制两份权限正文。

## Execution Mode

主控维护全图。高承重单边或循环可由隔离 Subagent 攻击，返回暂定判断、依据、强反例、边界和未知；主控负责全图一致性。

图工具表达不足时，以关系表为真源，图只作视图。

**Audit Hook**：更新「关键行为」「子 Skill 调用」「影响清单」「结果与验证」。
