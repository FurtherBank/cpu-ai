# 反推认知节点

## Input

- `cognition-contract.md`。
- `claim-ledger.md` 中允许建图的主张切片。
- 未决缺口索引。
- 现有目录仅在候选初稿完成后用于查漏。

## Goal

在 `system-map.md` 建立节点账。每个节点必须符合 [产物契约](../references/artifact-contracts.md) 的字段契约，并从具体 `from_state` 经一次 `change` 抵达可观察 `to_state`。

当每个保留节点都能说明删除后哪项能力失效，且 ready 节点同时满足：位置已确认、必需输入未阻断、条件进入 `scope_boundary`、推理桥和范围边界闭合时完成。`scope_boundary` 还要写明何时停止外推；位置 provisional 的节点即使主张可靠也不得 ready。

## Guidance

分别生成三路候选，不互相抄答案：

- 从终态回推必要前提。
- 从入口前推下一次合法认知增量。
- 假设教材形式完成但读者仍不能迁移，反演最早缺失的认知变化。

并置后逐个做删除反事实：删掉候选，哪项终态会失效，或下游会被迫补哪项本应由此节点完成的核心判断？回答不出则移出主地图。

节点粒度不是篇幅。一个主题含不同入口或终态时拆分；多个主题共同完成同一变化时合并。名称优先写成“区分……”“判断……是否……”“从……推到……”等动宾结构。

`ready` 只表示在当前限定下可安全叙述，不等于所有主张无条件为真。条件性主张必须连同条件进入节点边界。

异常处理：

- 候选与现有目录高度同构：隐藏目录，重做三路生成。
- 终态只能写“了解更多”：缩小或合并节点。
- 一个节点既 ready 又依赖阻断主张：拆出稳定部分，否则整节点 blocked。

## Execution Mode

主控执行。单个节点需要千字级判断时，可按 `f-attention-budget-constraint` 单独委派；一个 Subagent 只确认一个节点，主控维护节点间一致性。

**Audit Hook**：更新「关键行为」「影响清单」「结果与验证」，记录移除候选的理由索引。
