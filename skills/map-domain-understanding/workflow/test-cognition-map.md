# 独立测试体系认知地图

## Input

- 用户原始需求原文。
- 四个候选真源及版本。
- 从候选真源生成、与其同版本的 draft 叙事交接快照。
- 主控按固定协议实例化的测试用例清单和回开协议。

禁止传主控设计过程、自评、怀疑点、地图是否正确的引导结论和淘汰路线。实例化用例的可操作预期结果与通过判据必须传入，不属于这里禁止的“答案”。

## Goal

由 fresh-context Subagent 输出独立测试报告，不修改地图。每个用例必须含执行动作、预期、实际、结论、证据和最早应回开的阶段；叙事烟测还要逐份记录 `route_id`、`batch_id`、fixture 路径、内容 SHA-256 与通过/失败。报告须给出 `nextState: TEST_PASSED | REOPEN_REQUIRED | BLOCKED_READY`。

全部必跑用例和条件用例通过，且额外边界攻击没有未处理失败时完成。

## Guidance

固定用例族见 [独立测试协议](../references/quality-gates-and-reopen.md#独立测试协议)。主控负责把每项用例写成前提、fixture、逐步动作、预期结果、证据要求、通过判据、责任阶段和依赖回归用例；缺动作、预期结果或回开协议时，测试者拒绝测试。零基础顺读、按需跳读、条件迁移、删除反事实、新材料回开和叙事消费烟测必跑；争议内容或循环特征存在时加对应测试。

测试必须实际沿节点、边、路线和主张 ID 操作，不得只检查字段是否存在。测试者只定位失败与证据，不修图或给出整张替代地图。

全部通过时，额外攻击一个最可能失败的边界。无证据的“通过”视为未执行。

## Execution Mode

必须委派 fresh-context Subagent，使用 [独立测试派发模板](../templates/independent-test-prompt.md)。复杂地图可拆多个测试者，但每位只消费原始需求、候选地图、同版本 draft 叙事交接快照、固定测试协议和实例化用例清单。

失败后主控按最早责任阶段回开，修复、通过静态闸门，再由新的 fresh-context Subagent 重跑失败用例及其依赖回归。全部目标路线通过才进入可交接；安全子集及其与受阻部分的隔离测试通过时进入受限可交接；没有安全路线或无法证明隔离时进入阻断封口。

**Audit Hook**：父日志登记测试派发、结论、失败证据、回开和重测；纯 Task 不强制子日志。
