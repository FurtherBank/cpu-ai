# Agent 意图理解指引

## 目标

在接收到最上层指示后，先独立完成对指示的意图理解，形成准确、完整、依据充分的结构化意图定义，再进入任务规划与工作拆解阶段。

意图理解负责确定用户期待什么样的结果，而非决定如何实现结果。

说白了就是，先确认“什么结果才算完成”，再讨论“要做哪些工作才能得到它”。

## 基本原则

- 以用户的原始指示作为意图理解的根本依据。
- 结合任务现场的实际情况理解用户描述中的对象、概念、状态及其关系。
- 允许基于充分依据补充用户未完整描述的上下文，但不得凭空揣测用户的主观期待。
- 不得因为执行便利性、技术偏好或预设解决方案而改变对用户意图的理解。
- 不将用户未指定的实现细节、产品设计决策或额外优化目标纳入用户意图。
- 不将背景说明、原因解释或举例直接视为独立执行目标。

## 意图理解流程

### 拆解原始指示的语义结构

识别用户描述中的主目标、子目标、条件目标、背景信息、实现约束及其他要求。

建立各部分之间的语义关系，避免遗漏要求、错误合并独立目标，或割裂相互关联的内容。

此处拆解的是用户表达的意图结构，而非工作的执行结构。

### 建立最小充分的任务现场认知

根据意图理解的实际需要，调查并理解任务涉及的具体对象、当前状态、内部结构、关联关系、运行规则、历史约定及作用边界。

优先通过已有上下文、实际观察和非修改性调查获得必要信息。

不得将未经验证的现场假设当作事实。

### 定义各个意图单元

对于每一个独立的意图单元，明确表达以下内容：

- **原始指示：** 该意图对应用户描述的哪部分内容。
- **作用对象：** 用户希望改变的具体事物、内容或认知状态。
- **当前状态：** 作用对象目前所处的实际状态。
- **期望状态：** 用户期待作用对象最终达到的状态。
- **实现约束：** 用户明确规定的实现方式及限制条件。
- **状态不变项：** 实现目标过程中应当保持不变的内容。
- **补充上下文：** 根据任务现场和已有信息补全的内容，以及补全依据。
- **未确定事项：** 尚无充分依据确定、且可能影响意图理解的内容。

无法确定当前状态时，应明确标记为未知，而非编造初始状态。

对于调查、分析、咨询、创作类任务，状态转化可以表现为信息、认知或交付物的变化，不要求一定存在对外部事物的修改。

### 处理意图不确定性

区分以下情况：

- 可以通过调查客观现场消除的不确定性：优先调查。
- 可以根据已有信息充分推导的内容：补充并注明依据。
- 用户未指定且属于执行者自主决策范围的内容：留给任务规划。
- 涉及用户真实期待、缺乏充分依据且会实质性影响结果的内容：向用户确认。

不得为了使意图描述看起来完整而强行消除不确定性。

## 标准输出格式

先给出用户原始指示的结构拆解，再给出任务现场中与意图判断有关的事实。随后按意图单元输出状态转化定义。

每个独立意图单元使用以下结构：

### Intent Unit

- **意图编号：** 唯一编号，便于后续执行、验证和复盘追溯。
- **原始指示：** 对应用户原话或其明确部分。
- **作用对象：** 这部分意图作用于什么。
- **当前状态：** 现在是什么状态，事实不足时标记为未知。
- **期望状态：** 用户希望变成什么状态。
- **实现约束：** 用户明确指定的实现方式和限制条件。
- **状态不变项：** 完成转化时仍需保持的内容。
- **补充上下文：** 为理解意图而补充的事实或上下文。
- **补充依据：** 每项补充信息来自哪里，或由哪些事实推导得到。
- **未确定事项：** 仍不能确定、且可能影响目标定义的内容。

用户描述的结构不一定是多个平行的意图单元，也可能包含主目标、子目标、条件目标、全局约束和背景说明。由此形成的是意图结构，而不是任务执行结构。

意图结构与任务执行结构不要求一一对应。一个意图可能需要多个任务实现，多个意图也可能通过同一个任务实现。

## 意图理解质量检查

在进入任务规划之前，检查：

- 原始指示中的所有有效要求是否均已覆盖。
- 各意图单元的作用对象是否正确。
- 对当前状态的描述是否具有事实依据。
- 期望状态是否忠实于用户原始指示。
- 补充的信息是否具有充分依据。
- 是否引入了用户未提出的目标。
- 是否完整保留了用户指定的实现约束。
- 是否明确了应保持不变的内容和作用边界。
- 各意图单元之间是否存在遗漏、冲突或错误关联。
- 是否仍然存在足以影响后续目标定义的关键不确定性。
- 意图定义是否已经足够清晰，能够作为后续任务规划和结果验证的依据。

只有在关键不确定性已被调查、合理保留或交回用户确认后，才把意图定义交给任务规划。

## 阶段交接与意图变更

将经过检查的结构化意图定义作为后续任务规划的输入。

任务规划需要围绕已经明确的期望状态展开，不得擅自改变、缩减或扩充原始意图。

如果后续执行过程中获得的新信息实质性影响了原有意图理解，应重新进入意图理解阶段，更新相关定义，再调整任务规划。

实现困难不能成为擅自降低用户目标的理由。需要改变目标范围时，应把变化及其依据交回用户确认。

保留原始指示与结构化意图之间的对应关系，使后续执行、验证和复盘均能够追溯到最上层指示。

## 核心边界

意图理解不是创造目标，而是还原目标；不是规划工作，而是为工作建立正确的目标基准。

允许补充用户未完整描述的事实和上下文，不允许自行补充用户没有表达且缺乏充分依据的主观期待。
