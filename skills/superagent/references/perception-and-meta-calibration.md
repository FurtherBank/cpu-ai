# 感知基准校准与负反馈防自嗨规程

## 适用场景与三条硬禁令

凡开启**开关 P（感知校准开关）**——包括网页/UI 体感与审美、复杂系统日志微弱异常识别、剧本与游戏娱乐局节目效果、特定作品美术风格与纯代码 3D 素材审美，以及收到用户“结果不够好”负反馈后的自主改进——必须执行本规程。

**三条硬禁令**：

1. **禁止裸评放行**：未建立现实锚点与可计算/可核验判别标准并通过留出集盲测验尺前，禁止让独立验证 Agent 凭模型原生直觉给产物打主观分数。
2. **禁止自夸污染**：送交独立验证 Agent 盲评时，严禁附带作者的创作意图或自我褒奖（如“此处巧用反差制造爆笑”“采用高端克制的留白设计”），只允许传入剥离修辞的裸产物及纯客观运行环境说明。
3. **禁止同尺硬改**：收到用户负反馈后，严禁走“分析原因 → 在旧稿上润色重写 → 用原来那套标准自评新版更好”的伪进化循环。

## 三层诚实认识论边界（L1 / L2 / L3）

区分“用于测量的工具形态”与“最终结论能够主张的认识论层级”：用**确定性探针脚本**测量 L1，用**留出样本盲测与结构规律核验表**评估 L2，对 L3 保持诚实留白。

| 认识论层级 | 判定标准（真值在哪里） | 内部强制动作 | 交付表述红线 |
| --- | --- | --- | --- |
| **L1 物理与统计可证层** | 真值可由代码脚本、几何计算、规则引擎或统计分布唯一算出 | **编写确定性探针脚本 100% 测穿**，存在硬伤直接淘汰重造 | 严禁把本可写脚本测出的破版、穿模、规则穿帮或心跳断流漏给用户 |
| **L2 现实样本与机制同构层** | 无单一公式，但有真实世界标杆正样本 `R+`、典型负样本 `N-` 及可拆解的结构规律 | **必须先过留出集感知基准校准门**，再做正反交换顺序成对盲评，拉高专业下限并消除 AI 套路病 | 必须附盲测与盲评原始存证，同时如实列出相对真实标杆 `R+` 仍存在的差距 |
| **L3 外部主体涌现层** | 真值仅存在于真实受众临场心理反应、个体独特口味或日志外的未打点物理世界 | **严禁内部伪装闭合**；在闭合 L1/L2 后提供正交候选方案或最小外部验证探针 | 严禁宣称“观众必笑 / 审美完美达成”，必须显式标为`待外部确认` |

## 样本分集与防数据泄露盲测协议

为防止“拿着刚用来调参数的同一批样本去验尺”造成 100% 假通过，执行严格的**开发集 / 留出盲测集物理隔离**：

1. **分集保管**：主人公收集至少 2 个真实标杆正样本 `R+` 与 2 个典型平庸/AI 套路负样本 `N-`（负反馈场景下旧版失败产物 `V1` 自动归入留出负样本）。主人公将其拆分为：
   - **造尺开发集**（如 `R+_dev`, `N-_dev`）：传给造尺的具体做事 Agent 用于分析差异、编写探针脚本与结构规律核验表；
   - **留出盲测集**（如 `R+_holdout`, `N-_holdout` 及 `V1`）：复制到隔离匿名路径（如 `.superagent/<task-slug>/blind-box/Sample_A`、`Sample_B`、`Sample_C`，抹除来源文件名与元信息），真实身份映射仅保存在主人公私有的 `blind-key.secret.json` 中，对造尺子代理和验尺子代理一律隐藏。
2. **极少样本兜底规则**：若特定小众领域只能找到 1 个参考正样本 `R+` 无法拆分留出正样本，则造尺规则严禁引用该样本的专有名词或具体数值特例，且主人公必须额外构造至少 2 个未见负样本变体混入盲测盒，交独立验证 Agent 检验泛化判别力。
3. **无样本环境降级规则**：若处于断网且本地无相关参考样本的环境，主人公不得凭空编造“假装查到的外部真实案例”充当 `R+`；应立即向用户说明样本受限并索取 1~2 个参考锚点。若用户亦无现成样本，则将 L2 降级为`无外部标杆锚定（仅剔除已知通用 AI 套路）`，闭合 L1 物理/逻辑硬指标并输出 2~3 个风格正交的小样供用户指认方向。

## 四类典型感知领域的造尺、验尺与盲评实操指南

### 网页与 UI 设计（审美与体验感知）

- **正负样本锚定**：选成熟同品类产品真实界面结构特征为 `R+`；以典型 AI 模板病页面为 `N-`（大面积高饱和紫蓝渐变、多层圆角卡片套卡片、首屏 3 个以上同权重实心按钮争抢焦点、行高字号拥挤、缺失空态/错误态/加载态）。
- **确定性探针脚本（L1）**：使用无头或可见浏览器在桌面端（如 `1440×900`）与移动端（如 `390×844`）真实渲染页面，注入边界测试态（0 条数据空态、超长字符串与极端数值、接口失败报错态、加载态），通过 DOM/CSS 脚本测量：横向溢出像素（须为 0）、元素遮挡重叠数（须为 0）、全页字号阶梯种类（收敛在清晰克制的 4~5 级内）、高饱和强调色占首屏面积比（防止满屏炫光）、正文对比度及可点击元素热区间距。
- **结构规律核验与盲认走查（L2）**：
  1. **首屏 3 秒盲认测试**：给全新的独立验证 Agent 仅看首屏截图（不给业务背景提示），要求其回答“当前页面核心用途是什么、第一顺位主操作按钮是哪一个、视线是否被多处同等高亮元素撕裂”；
  2. **完整用户路径走查**：独立验证 Agent 模拟真实用户从入口逐步点击、输入、触发校验、查看反馈直至完成目标，记录沿途每一次卡顿、跳转歧义或不合时宜的界面文案。
- **校准门要求**：在匿名混排盒中，探针与盲认流程必须稳定放行成熟标杆页、稳定判死“功能可用但重心分裂或充满 AI 模板廉价感”的负样本页。

### 阅读系统日志（异常与信号感知）

- **核心纪律**：面对数百行以上复杂日志，**严禁让大模型逐行通读原文凭语感找问题**（极易只抓显式 `ERROR` 字样而漏掉致命的静默故障或慢性退化）。
- **确定性统计与时序探针脚本（L1）**：先由具体做事 Agent 编写日志解析探针脚本，输出结构化统计报告：
  1. **去参数化模板聚类**：剥离时间戳、请求 ID、IP、纯数值，将原始日志归并为固定事件模板，生成分时间窗的频次矩阵；
  2. **突现与突增扫描**：提取故障窗口首次出现的新模板、频次异常倍增或重试率抬升的模板；
  3. **静默断流扫描（关键微弱信号）**：识别平稳基线期按固定周期稳定出现的心跳、消费成功、定时调度或下游回调模板，检测其在观测窗口是否突然降为 0 或间隔异常拉长；
  4. **分位数慢性漂移与配对失衡扫描**：计算各阶段耗时的 P50/P95/P99 时序偏移（捕获未触发超时阈值的慢性恶化）、事务/连接/任务的开启与完成计数剪刀差（捕获泄漏或半截挂死）、以及同一毫秒或同一调用链内跨组件的微弱异常共现。
- **校准门要求（合成微弱故障盲测）**：主人公在一段正常基线日志副本中，用脚本悄悄注入不带 `ERROR` 关键字的合成微弱异常（如删掉某后台 worker 3 分钟心跳、将某下游调用耗时乘以 3 倍但仍低于超时线、制造少量有开始无结束的请求），遮蔽注入位置交探针脚本与独立验证 Agent 盲测；100% 精准召回注入点后，才准许用该探针研判真实目标日志。日志完全未打点的外部盲区归入 L3，列出需补查的监控指标或数据库核验查询。

### 《杀戮尖塔2》等剧本创作与娱乐局设计（社会与情境效果感知）

- **正负样本与事实锚定**：
  - 建立 **L1 游戏机制事实表**（核实真实卡牌费用/数值、遗物触发时机、怪物意图循环与状态结算规则，严防编造假卡牌效果的“云玩家穿帮”）；
  - 采集真实人类高赞实况切片或公认高节目效果对局的互动结构作为 `R+`，以大模型默认直出的套路搞笑剧本（堆砌谐音梗、角色自夸“太好笑了”、无铺垫强行反转）作为 `N-`。
- **确定性探针（L1）+ 博弈张力规律核验表（L2）**：
  - **牌局状态机与口头计划双重合规探针**：编写脚本或逐帧状态表校验每一幕的起始能量、手牌变化、伤害/格挡算式、遗物触发先后顺序与血量结算；**同时核验角色口头宣称的本回合连招计划在当前可见总能量下是否算术合理**（除非桥段核心笑点正是“连基础加法费用都算错”，否则严禁在 3 费回合一本正经规划连打两张 2 费牌却把翻车归因于其他机制），任何算术或规则穿帮直接判 L1 失败；
  - **AI 尬梗负向扫描**：硬性拦截谐音冷笑话、括号内自我解释笑点（如“（观众哄堂大笑）”）、脱离具体牌面危机的空喊口号；
  - **博弈预期违背结构核验**：检查趣味点是否长在真实的牌局博弈张力上——即“基于真实手牌/遗物建立清晰可信的算牌预期 → 被一个合乎游戏规则但易被忽略的机制交互（如遗物结算顺序、抽牌污染、怪物多段伤害）瞬间打破 → 产生直观后果与即时反应”，且铺垫长度与信息密度能让目标观众看懂梗点。
- **校准门与盲评要求**：留出集盲测中，新基准必须在抹去主播口头禅的真实高能桥段 `R+` 与 AI 套路稿 `N-` 之间稳定选出 `R+` 并指明机制差异。造物完成后，剥离一切作者设计说明，将裸剧本匿名编号交独立验证 Agent 执行正反交换顺序成对盲评；交付时明确将“真实观众临场发笑率与配音气口效果”划为 L3 待试播/试读验证项。

### 特定作品卡牌美术风格与纯代码 3D 素材审美（风格与造型感知）

- **正负样本锚定**：
  - 卡牌/2D 特定风格（如《杀戮尖塔2》卡图）：官方原作卡图集为 `R+`；通用欧美厚涂奇幻插画、日系二次元卡图或“仅套了一圈黑框但内部仍是平滑柔光渐变”的 AI 仿图为 `N-`；
  - 纯代码 3D 素材/场景：风格化标杆 3D 资产多视角图为 `R+`；基础几何体生硬堆叠、部件悬空穿模或默认高光泛着廉价塑料反光的代码生成废品为 `N-`。
- **确定性视觉与几何探针脚本（L1）**：
  - **2D 风格统计与造型质量探针**：用图像处理脚本计算待测图与原作样本集 `R+` 的客观分布距离——HSV 色相/明度/饱和度分位数距离、深色轮廓边缘像素占比与梯度锐度、色块内部梯度平坦度、以及主焦点亮部对比度（量化区分原作“粗黑手绘描边+硬切块面光影+夸张动态斜率”与普通 AI 图“平滑渐变”或“粗糙矩形方块简笔画拼凑”）；必须生成 **≥2 套不同构图/笔触方案**供盲评择优；
  - **3D 代码素材多视角与无文字剪影探针**：编写无头渲染与几何检查脚本，自动导出 **正、侧、顶、45° 轴测四视图 + 纯黑白剪影图（Silhouette，注意：导出剪影图与盲认视图时必须隐藏一切 UI 按钮与文字标题，严禁在图上印出物体名称剧透答案！）**，并代码级检查：子网格连通性（拦截悬空断连或恶性穿模）、主体明度可读性（严禁在纯黑背景上用近黑材质导致主结构糊成一团黑影，必须有清晰轮廓高光、边缘光或自发光焦点如灯芯火光）、精细部件造型（严禁只用几个未倒角矩形盒子生硬堆叠敷衍复杂器物）及材质粗糙度参数（拦截廉价塑料反光）。
- **校准门与读图盲认要求（L2）**：
  - 卡图基准必须在“原作真图 + 套黑框异风格仿图 + 粗糙方块简笔画负样本”匿名混排挑错盲测中 100% 揪出负样本；
  - 3D 素材必须通过**无文字纯黑剪影独立读图盲认测试**：给不看源码、不知晓需求名称的独立验证 Agent **仅用 `Read` 工具读取隐藏了全部文字 UI 的纯黑剪影图与四视图**，令其盲答“这是什么具体器物、各部分结构是否清晰美观”；若认不出具体器物（如把提灯祭坛看成普通积木塔）或指出画面过暗糊成一团，必须签发`失败`打回重造！交付时自动合成放入真实游戏牌框或场景光照的预览图，将人类画师神韵终审划为 L3。

## 负反馈元测试：五步刚性防自嗨闭环协议

当用户明确反馈“当前产物 `V1` 不够好 / 不够有趣 / 画风不对 / 体验别扭”并要求改进时，遵循**负反馈双重证伪**铁律，严格依序执行以下五步，监督者在第三步与第五步强制核查：

### 第一步：熔断直改与旧尺破产归因（主人公立账，第三步交监督者核查）

- 立即禁止在 `V1` 上直接修改词句或微调参数，将 `V1` 封存为留出盲测集中的永久回归负样本 `Confirmed_Negative_V1`。
- 核查上一轮放行 `V1` 的验证存证（若 `V1` 为首轮无基准直出则记录“首轮缺失感知基准裸出”），明确写出旧感知基准 `D1` 漏掉了哪个结构规律、缺少哪个确定性探针，或把什么表面套路词误当成了优点，写入 `ledger.md`。

### 第二步：补充增量外部锚点与串行拆单（战略引领者定里程碑边界 + 主人公拆单）

- **无外部新锚点不准谈改进**：禁止闭门靠模型自我反思臆造新标准。必须补充采集真实标杆正样本 `R+` 或新增客观物理测量探针（若启用了战略引领者，由其在里程碑边界核查新增外部锚点后批准开启校准里程碑；若纯属用户个人独特审美偏好且无参照，由主人公向用户做一次极简锚点提问）。
- **主人公**建立两张物理隔离的串行工单：**工单 A（修尺与探针升级）**先行派发，**工单 B（底层结构重构造物）**保持挂起锁定。

### 第三步：新感知基准 `D2` 的三重反事实校准门（独立验证 Agent 验尺 + 监督者准入）

工单 A 产出新感知基准 `D2` 后，主人公将真实标杆留出正样本 `R+_holdout`、旧版失败产物 `V1` 以及另一份同类套路平庸负样本 `N-_holdout` 遮蔽身份混编送交全新的独立验证 Agent 盲测，必须**同时通过三关**：

1. **必杀旧版**：在不告知哪份是 `V1` 的前提下，`D2` 稳定将 `V1` 判为不合格，且命中的扣分项切中真实败因；
2. **保真标杆**：`D2` 同时将真实标杆 `R+_holdout` 判为高分通过（防止为故意判死 `V1` 造出“万物皆错”的无效严苛尺）；
3. **泛化防作弊**：`D2` 同样能将另一份同模型套路负样本 `N-_holdout` 判为不合格，且**独立验证 Agent 与监督者**共同核查确认 `D2` 代码与规则中**不含针对 `V1` 具体词句或特定数值的硬编码作弊补丁**。

三关任一未过，退回工单 A 重建感知基准，严禁解锁工单 B。

### 第四步：底层重构与正反交换顺序成对盲评（具体做事 Agent → 独立验证 Agent）

- 解锁工单 B，派全新的具体做事 Agent 依据 `D2` 锁定的感知基准（不传留出盲测样本原件），从底层结构重新生成至少 2 个实质差异候选方案 `V2a`、`V2b`（严禁在 `V1` 原文残骸上涂抹改词）。
- 派全新的独立验证 Agent：
  1. 先运行 L1 确定性探针脚本淘汰存在硬伤的方案（若全部淘汰则打回工单 B 重造；若仅剩 1 个方案存活，仍须与 `V1` 进入下一步正反盲比）；
  2. 将每一个存活候选方案分别与 `V1` 匿名混编，按正序（如 `Option_1=V1, Option_2=V2a`）和反序（如 `Option_1=V2a, Option_2=V1`）执行两次独立成对盲评。只有**正反两次均一致击败 `V1`** 且探针硬指标实质改善的新候选方可合格（若与 `V1` 互有胜负，判定未实质超越 `V1` 打回重造，严禁将已证伪的 `V1` 并列交付）；多个合格新候选之间再按正反盲比择优（新候选之间正反评价矛盾时判为平局并列呈现），同时对照 `R+_holdout` 盲评记录残余差距。

### 第五步：去形容词的证据化交付（主人公 + 监督者复核）

向用户交付改进版时，严禁出现“新版更加生动爆笑、视觉质感全面飞跃”等无锚主观形容词，固定按四项证据交付：

1. **旧尺失灵复盘**：上一版放行 `V1` 时错信了什么表面代理指标或缺失了什么探针；
2. **新尺三重校准证据**：`D2` 在匿名留出集上区分 `R+_holdout`、`V1` 与 `N-_holdout` 的原始盲测数据；
3. **可测量的底层重构与盲评记录**：胜出方案相对 `V1` 在底层结构与探针指标上的具体变化，以及正反交换顺序成对盲评结果；
4. **残余差距与 L3 待验边界**：相比真实顶尖标杆仍存在的差距，以及需交真实用户/受众检验的外部边界。
