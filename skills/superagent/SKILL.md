# SuperAgent 协作与感知校准工作流

## 本 Skill 每次产出什么

把复杂任务或缺少显式判据的质量要求，转化为**权责排他、过程受控、判据先验、能够合法终止**的交付闭环。接手当前会话的 Agent 默认担任**主人公**，其余职责单元按条件启用，不为简单任务强凑满编团队。

## 术语速览

- **有限任务**：有明确验收终点、满足约定条件即可正式结项关闭的单次任务（区别于长期驻守监听事件的持续服务）。说白了就是“干完验收合格就能交差收工的活，不是没完没了的值班”。
- **主人公**：当前任务的默认直接负责人，统筹目标澄清、拓扑选择、子代理调度、产物合龙与有限任务关闭判断。说白了就是“全程盯到底的总负责人，不能只发任务不管合拢和交差”。
- **决定对象**：某一职责单元唯一有权拍板生成或改写的那类结论。说白了就是“这件事归谁拍板，其他角色只能提证据或建议，不能直接动手改”。
- **控制脑裂**：主人公与监督者在不同步的观测窗口下，同时对同一个具体做事 Agent 下发暂停、重试或改向指令的现象。说白了就是“两个人同时抢一个方向盘和急刹键，两边都不知道对方刚踩了什么”。
- **共享骨架**：并行派发多个具体做事 Agent（或开启开关 P 锁定感知基准）前必须先锁定的全局接口、状态不变量、术语表或感知基准。说白了就是“分头施工前先焊死公共底盘，免得最后拼成缝合怪”。
- **阻断条件账本**：记录距离当前有限任务合法结项还差哪些必要条件的清单。说白了就是“不看今天干了多少活，只看离合法交差还剩几个硬门槛没清零”。
- **回开**：当新证据推翻已锁定的上游目标、共享骨架或感知基准时，正式撤销上游锁定状态并退回上游重新决策（区别于同一标准下独立验证 Agent 将不合格产物**打回返修**）。说白了就是“发现图纸本身画错了，退回去重改图纸，而不是逼施工队按错图纸硬改”。
- **感知基准校准门**：缺乏现成确定性判据时，正式生成产物前必须通过的前置关口——用留出的现实正样本与负样本对**感知基准**（确定性探针 + 结构规律核验表）做遮蔽身份的盲测，证明它真能稳定分出好坏。说白了就是“拿尺子量新东西前，先用真货和次品试一下尺子准不准；尺子测不准就不许开工”。
- **负反馈双重证伪**：当真实用户或外部实验指出当前产物 `V1` 不够好时，既判定 `V1` 不合格，同时判定上一轮放行 `V1` 的旧感知基准 `D1` 已经失灵。说白了就是“用户说东西差，说明东西不行、上次夸它行的旧尺子也坏了，绝不能拿旧尺子量新版自夸进步”。

按需读取一层配套规范：

- 五类职责单元排他权限、派发模板与存证目录协议：读取 [references/role-and-handoff-contracts.md](references/role-and-handoff-contracts.md)（启用任何子代理前必读）。
- 基础执行拓扑与特性开关选择、双模态收敛与关闭审计：读取 [references/task-modes-and-convergence.md](references/task-modes-and-convergence.md)（非单体直连拓扑必读）。
- 网页体验、日志异常、剧本/娱乐局、视觉风格/3D 素材及负反馈迭代校准：读取 [references/perception-and-meta-calibration.md](references/perception-and-meta-calibration.md)（开启感知校准开关时必读）。

## 启动前模式判定与状态账本初始化

先检查核心目标、价值取舍或不可逆外部操作授权是否存在改变主干的分歧；若有，先查证事实或向真实用户确认，**禁止用任务拆解掩盖目标未定**。

随后分两步确定运行配置（细则见 [references/task-modes-and-convergence.md](references/task-modes-and-convergence.md)）：

### 第一步：三选一确定基础执行拓扑

| 任务可分性与规模 | 基础执行拓扑 | 执行规则 |
| --- | --- | --- |
| 目标无歧义、单一写域、几步内可完且未开开关 P/S | **单体直连拓扑** | 主人公独立完成并做确定性自检；未开开关 G 时**免建 `.superagent/` 账本、免拆子代理**（若开启开关 G 如单步不可逆写或紧急止血，建最小 `ledger.md` 走授权/旁路记录门，无需强拆复杂子代理） |
| 强连续推理、热点调优或单篇短文，切分会丢中间状态 | **单写者深潜拓扑** | 派单一具体做事 Agent 连续推进（主人公保持调度与送检中立），产物冻结后交独立验证 Agent 验收 |
| 两个以上模块且可隔离写域 | **多写者合龙拓扑** | 主人公先冻结**共享骨架** → 划定排他写域并行派发具体做事 Agent → 主人公合龙后交独立验证 Agent 跑端到端路径 |

### 第二步：按条件叠加正交特性开关（可多选组合）

- **开关 P（感知校准开关）**：涉及审美体验、复杂日志微弱信号、幽默剧情与娱乐效果、特定作品风格/3D 代码素材审美，或收到“结果不够好”的负反馈时**必开**，且**自动联动启用开关 S 中的监督者**（至少为快照监督）。若与“多写者合龙拓扑”同时开启，先完成感知核心的造尺验尺并锁入**共享骨架**，再分模块合龙。
- **开关 S（战略与监督开关）**：跨多里程碑演进时启用**战略引领者**（由外层调度或主人公在里程碑边界唤起独立战略子代理在用户授权框内定阶段目标）；存在长链路、多子代理合龙、感知校准或返工扩界风险时启用**监督者**。
- **开关 G（高危与价值门禁开关）**：
  - 含生产发布、删除、付款等不可逆外部写操作：穿透至真实用户确认，未获放行前挂起；
  - 线上故障秒级紧急止血：预置安全红线内先由主人公直接执行止血动作以保恢复速度，**止血动作完成后立即升级为单写者深潜拓扑，补唤起独立验证 Agent 与监督者做盘后复核与审计记录**；越出预设红线的不可逆动作一律挂起等人类确认；
  - 无客观唯一真值的主观路线抉择：不替用户选边站，并行产出满足全部硬约束、代表不同取向的多套备选方案及各自代价，由独立验证 Agent 担任红队挑刺后交真实用户拍板。

凡**非单体直连拓扑**（注意：**一旦开启开关 P 或开关 S，严禁选用单体直连拓扑，必须至少选用单写者深潜拓扑或多写者合龙拓扑，强制唤起真实的独立子代理**），主人公必须在派发子代理前初始化任务工作目录（若用户指定了任务专属目录 `<task-dir>` 则建于 `<task-dir>/.superagent/<task-slug>/`，否则建于当前工作区 `.superagent/<task-slug>/`，其中 `<task-slug>` 用英文短横线命名并在同任务多轮对话中复用）：

- **主人公排他维护 `ledger.md`**：写清目标与消费者、状态分层（严格区分已证实事实、合理推断、待验假设、有效授权决定、关键未知）、成功与停止条件、当前模态（根因/机制/基准尺未确立时标为`探索态`，确立锁定后切换为`收敛交付态`）及**阻断条件账本**（`B1, B2...`）。
- **子代理独立只读存证 `runs/<序号>-<角色>[-阶段].md`**：每个子代理各自将完整原始输出写入 `runs/` 下的独立文件并附带**产物指纹**（统一取 `shasum -a 256` 前 12 位十六进制字符），主人公在 `ledger.md` 中引用存证路径，避免并发写冲突，并防止主人公向监督者隐瞒历史打回记录。

微型示例：用户要求“给《杀戮尖塔2》设计一段有节目效果的娱乐局剧本”。主人公判定选**单写者深潜拓扑 + 开关 P + 开关 S（快照监督）** → 建 `.superagent/sts2-entertainment-script/ledger.md`（初判`探索态`） → 禁止直接写剧本，先走造尺与留出集盲测验尺，通过后切入`收敛交付态`生成候选剧本并做剥离舞台解释的盲评。

## 五类职责单元的排他运行铁律

1. **战略引领者**：只在人类有效授权框内决定阶段定位、下一里程碑聚焦方向、里程碑成功/停止条件及是否继续迭代，输出写入 `runs/<序号>-strategy.md` 由主人公同步至 `ledger.md`。不拆解具体实现，不越权批准不可逆外部动作；在开启开关 P 的任务中若无新增外部锚点或基准增量，禁止自动续杯新里程碑。
2. **主人公**：独占当前里程碑内的拆解、**共享骨架**锁定、排他写域分配、具体做事 Agent 的启停重派、产物合龙、`ledger.md` 更新与有限任务关闭判断。禁止将重叠可变写域并行派给多个具体做事 Agent；禁止削弱上层成功条件强行清零**阻断条件账本**；非单体直连拓扑下禁止自审自结。
3. **监督者**：直接扫描 `ledger.md` 与 `runs/` 下全部原始存证及实际产物文件，独立诊断偏航、空转或扩界，输出写入 `runs/<序号>-supervisor.md`。
   - **禁止控制脑裂**：只要主人公正常响应，监督者不得绕过主人公直接暂停、重试或改向单个具体做事 Agent，而是向主人公发出带证据路径的限期纠偏单并追踪闭环。仅当主人公失联死锁、伙同扩界或触碰未授权高危红线时，直接升级至战略引领者或真实用户。
   - **双模态收敛审计**：`探索态`考核每轮是否凭实证排除了旧假设或补齐关键事实（拦截原地空转）；`收敛交付态`考核剩余阻断条件是否净减少（拦截局部完美主义与偷塞计划外优化）。
   - **诚实声明运行形态**：具备后台进程或外部巡检会话时运行持续外置监督；单会话环境下由主人公在固定关口（共享骨架冻结后、验尺揭盲后、产物合龙后、同一阻断项验证打回满 2 次时、拟结项前）唤起无历史继承的独立子代理扫描 `runs/` 全量记录执行快照监督，并如实标明`快照监督`。
4. **具体做事 Agent**：只接收单一聚焦命题与排他可写范围，将界内产物落盘并将施工自检原始日志、**产物指纹**与已知局限写入 `runs/<序号>-worker.md`。允许运行本地编译或确定性脚本自检，但**禁止充当独立验证 Agent 的雇主、传话人或结果过滤器**；需改动界外**共享骨架**时必须停工上报主人公。
5. **独立验证 Agent**：由主人公在造尺完成或产物合龙冻结后直接唤起，接收**原始任务契约 + 已校准探针/验收标准 + 剥离了作者自夸辩解的裸产物**（客观报错与施工已知局限清单可附带，主观创作吹嘘一律剥离），独立执行检查并将原始证据与`通过 / 失败 / 未验证`裁定写入 `runs/<序号>-verifier.md`。禁止替具体做事 Agent 修改核心业务产物；宿主无独立子代理能力时，主人公只能将验收项记为`主人公降级自检（未完成独立验证）`，结项时状态只能标为`产物已交付，待独立验证`。

## 感知校准与负反馈元测试硬流程

凡开启**开关 P**，必须读取 [references/perception-and-meta-calibration.md](references/perception-and-meta-calibration.md) 并严格按序过关：

1. **旧尺破产归因（仅收到负反馈时先执行）**：执行**负反馈双重证伪**，立即冻结在旧版 `V1` 上的直接修改，将 `V1` 封存为永久回归负样本，核查上一轮放行 `V1` 时漏掉了什么现实规律或误信了什么表面套路指标，记入 `ledger.md`。
2. **分集采集锚点与先造尺**：主人公收集目标领域真实标杆正样本 `R+` 与典型平庸/AI 套路负样本 `N-`（断网且无本地样本时，向真实用户索取最小参考锚点；若用户也无法提供，明确降级为仅保证物理逻辑自洽并交付多风格小样供用户指认）。主人公将样本切分为**造尺开发集**与**留出盲测集**（负反馈下 `V1` 必入留出盲测集；样本极少无法切分时，后续验尺必须追加未见合成反例）。派具体做事 Agent 基于造尺开发集构建**感知基准**（确定性物理/统计探针脚本 + 结构规律核验表）。
3. **留出集盲测先验尺（感知基准校准门）**：主人公将**留出盲测集**遮蔽真实身份编号（如 `Sample_1, Sample_2...`），连同待验**感知基准**交给全新的独立验证 Agent 盲测，并由独立验证 Agent 与监督者共同核查探针代码与规则中是否存在针对特定字句/数值的硬编码作弊补丁。主人公对照密钥揭盲：只有稳定放行留出 `R+`、稳定判死留出 `N-`/`V1` 且无作弊补丁时，才将该感知基准锁入 `backbone.md` 并切入`收敛交付态`；否则打回重修。
4. **隔离样本后造物**：另起全新的具体做事 Agent（传入已锁定的**感知基准**，不传盲测样本原件），从底层结构生成**至少 2 个具有实质机制/布局差异的候选方案**（可由 1 个子代理分出两套正交方案或并行派 2 个子代理各自独立构造；负反馈下禁止在 `V1` 原文上做局部词句涂抹）。
5. **去偏成对盲评与三层诚实定界**：派全新的独立验证 Agent 先跑确定性探针脚本淘汰硬伤方案（若全部淘汰则直接打回重造），再对存活候选执行匿名**正反交换顺序的两次成对盲评**（消除位置偏见）：负反馈场景下**每一个存活新候选都必须与 `V1` 做正反盲比且一致击败 `V1` 方可合格**（若与 `V1` 互有胜负则判未实质超越、打回重造，严禁将已证伪的 `V1` 并列交付）；非负反馈下若仅存 1 个存活候选亦须与 `N-` 正反盲比胜出；多个合格新候选之间正反盲比择优（新候选之间正反结果矛盾时判为平局并列呈现）。最终按三层认识论边界诚实交付：
   - **L1 物理与统计可证层**：探针脚本实测 100% 达标（零破版、零规则穿帮、统计信号全召回）；
   - **L2 现实样本与机制同构层**：附盲测校准与成对盲评原始数据，说明相对 `N-`/`V1` 的可测量结构改进及相对真实标杆 `R+` 的残余差距；
   - **L3 外部主体涌现层**：真实观众发笑率、个体独特审美偏好或日志外的未打点物理根因——严禁自评“爆笑/惊艳”，显式标为`待外部确认`并给出最小外部测试探针或正交备选方案。

## 隔离派发与熔断升级规则

- **无倾向隔离派发（严禁跳过子代理探测偷懒自检）**：
  - 在 Cursor 环境中，`Task` 工具可能位于动态工具命名空间 `cursor` 下——**必须先调用 `GetDynamicTools({"namespace": "cursor", "toolName": "Task"})` 获取 schema，再调用 `CallDynamicTool({"namespace": "cursor", "toolName": "Task", "arguments": {"subagent_type": "generalPurpose", "description": "...", "prompt": "..."}})` 创建全新子代理（严禁传 `resume`）**；若顶层已有直接 `Task` 工具则直接调用。**未经 `GetDynamicTools` 实际调用报错，严禁谎称“宿主无独立子代理能力”而降级自检！**
  - 在 Codex 环境中使用 `collaboration.spawn_agent` 并设 `fork_turns: "none"`；其他环境采用同等零历史继承调用。派发提示词省去主人公的个人倾向与暗示答案的措辞。
- **回开与验证拉锯熔断**：当新事实推翻上游目标、**产物指纹**失配、写域冲突或真实外部反馈否定内部结论时，立即**回开**对应上游节点。同一阻断项在具体做事 Agent 与独立验证 Agent 之间连续**打回返修满 2 次**仍未通过时，主人公立即停止第 3 次盲改，唤起监督者扫描 `runs/` 审计原因：属里程碑范围/技术口径权衡但仍在人类授权框内的交战略引领者裁决；属核心价值偏好、验收底线分歧或未启用战略引领者的，直接打包双方证据交真实用户裁决。

## 结项关闭审计与交付结构

宣告有限任务结束前，主人公必须逐条完成以下物理核验（单体直连拓扑仅做本地确定性自检）：

1. **打回必重验核验**：检查 `runs/` 下最新一份 `*-verifier*.md` 原始结论必须为`通过`且其检验的**产物指纹**与当前磁盘最终交付物完全一致——**严禁在某次验证签发`失败`并补改文件后，跳过重派新的独立验证 Agent 就直接在 `ledger.md` 中谎标“已通过”**！
2. **收尾监督存证核验**：凡开启开关 S（含开启开关 P 自动联动启用监督者的情形），`runs/` 目录下**必须实际存在覆盖最终待交付状态的 `*-supervisor*.md` 监督发现单**，且其中指出的纠偏项已全部闭环；缺此存证文件严禁宣告结项。

核验无误后，向用户输出：

- **运行配置与启用职责**：基础执行拓扑、开启的特性开关、实际运行的职责单元与监督形态（持续外置监督 / 快照监督 / 单体免启用）。
- **核心结论与交付产物**：产物路径、最新**产物指纹**及当前结项状态（从四项互斥状态中严格择一标明：`目标已达成` / `产物已交付，待外部确认` / `产物已交付，待独立验证` / `受阻升级待裁决`）。
- **验证与校准证据**：L1 确定性探针实测数据；若开启开关 P，附上旧尺失灵原因（负反馈场景）、留出集盲测验尺记录与正反顺序成对盲评证据（禁用无证据主观形容词自夸）。
- **未决事项与外部边界**：L3 待真实受众/生产环境验证项、延期移交的非阻断尾项及后续**回开**触发条件。
