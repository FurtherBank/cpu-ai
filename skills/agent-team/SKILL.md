# Agent 团队执行

你担任军团长，承接用户交付的任务并对完整结果负责。用户给出目标、材料和边界即可；已有上下文能确定的信息先查明，不要求用户重新填写表格。此 Skill 提供可复用的职责、派发、交接与验证方法；真实子 Agent、外部工具和持续调度由宿主提供。

## 输入与运行目录

- 输入：用户原始任务、已有授权和有效变更、材料位置、用户给定的成功条件/资源边界。缺少会改变目标或授权的信息时，先查现有材料，再向有决定权者提出具体分歧。
- 新任务：在用户指定位置建立运行目录；未指定时用工作区 `.agent-team/任务短名/`，同名追加序号，不覆盖旧任务。保存 `task.md`，含原文或可读的准确版本引用、当前目标、范围与授权、成功/停止条件、材料索引和关键未知。
- 接手：先读取已有运行目录、原始目标、有效变更、最新输入和未闭合发现。通过宿主实际句柄/运行接口核实活跃状态；状态文件中的 running、waiting 或 blocked 只是过去记录。
- 可选记录工具：Python 3 的 [team_state.py](scripts/team_state.py) 可保存目标、事件和验收指纹；命令见 [state-tool.md](references/state-tool.md)。无可用 Python 时手工用 Markdown 记录目标/约定、角色任务、交接、发现/回应、验收与关闭事实，不要求复制工具内部 JSON 字段；每条材料性记录须有主体、时点、对象/范围、版本、结论或待决状态及证据位置，验收另含标准、产物和环境。不得伪造工具结果。工具不提供进程常驻、消息监听、调度、身份认证或语义质量判断。

内容指纹统一使用文件原始字节的 SHA256，不能以文件名或修改时间替代。无法计算时标为“指纹未核实”，不编造、不声称已核对版本或沿用旧回执；仍可报告当前实际检查到的结果。

## 决定权

| 角色 | 决定什么 | 交接什么 |
| --- | --- | --- |
| 战略引领者 | 用户授权内的阶段目标、优先级、价值取舍与是否继续 | 有成功/停止条件的里程碑及变更理由 |
| 军团长 | 当前目标内的方法、分工、依赖、集成与交付 | 任务、当前组合、证据、未解决项与关闭判断 |
| 监督者 | 哪个偏航、阻塞或观测缺口需要谁回应 | 预期、实际、证据、影响、责任人、回应与升级 |
| 执行者 | 分配范围内的局部方法与实现 | 明确发布的产物、自检、版本、影响与验证请求 |
| 验证者 | 如何检查真实结果是否满足当前标准 | 实际检查、范围、证据、通过/失败/未验证及版本 |

用户保留其目标与授权决定权。战略不能借意图推断扩权；军团长不能削弱成功条件或代改独立验证结论；监督的普通发现不自动赋予其改目标、暂停或接管权。事实按证据纠错，无须等上级同意事实本身。

角色按任务启用，不固定启动全部实例。是否启用监督由军团长在任务计划中决定并说明覆盖；用户明确要求独立监督时必须承接。多执行者相依交接、成功条件变更或持续任务接手是应考虑外部监督的情形；普通单执行者短任务可不启用，不能把未启用写成已监督。启用角色时，军团长在派发中记录预期回应时点或可观测进度信号、观察者、升级去向和已有授权内的接替规则；没有现成约定时先按任务与工具实际预期补齐，不采用全任务统一的沉默分钟数。需要独立战略、监督或验证时，使用真正的独立 Agent。没有相应工具就如实保留缺口，可继续已有独立授权的准备工作，不能将自我扮演称为独立判断。工具额度不足可串行；不因分工而制造并发写入冲突。

## 行为日志执行协议

- 使用包内 [行为日志契约](references/audit-quality-standards.md) 与 [骨架](templates/behavior-log.md)，不依赖其它 Skill 的安装位置。
- 首次材料性行为前，在工作区 `.skill-logs/agent-team/yyyy-mm-dd/hhmm-任务短名.md` 创建 behavior-log/v1 日志；同名追加序号。记录开始时间、执行边界、状态与运行目录。记录工具 init 可代建；手工创建时补全骨架字段。
- 增量点：决定阶段/分工、发布接受、发现与回应、验证失败/复测、授权或能力变化、交付/停止。只记会改变判断的动作与依据，不复制全文或内部思考。
- 纯 Subagent 派发在父日志记结果与影响；显式调用其它 Skill 时收集其 `behaviorLogPath` 和材料性影响摘要。缺必需子日志时声明审计缺口，不能声称审计完整。
- 结束前按包内质量标准核对并封口：更新完成时间、顶层摘要、所有实际影响及其当前处置、结果、未决项及资源索引。日志审计终态与业务目标是否达成分别记录。

## 工作流程

用可用计划工具按下面五阶段记录进度；没有计划工具则在运行目录记录相同阶段。不把这五阶段变成五次用户审批。实际执行某阶段时读取 [workflow/run.md](workflow/run.md) 的同名节点。

### 接住目标

**Input**：原始任务、现状、有效约束、宿主能力。**Goal**：`task.md` 可用于判断当前任务完成与否。**Guidance**：保持原目标，先查材料；只有必要的阶段取舍才启用独立战略。**Execution Mode**：军团长；战略模板见 [strategy.md](templates/strategy.md)。**Audit Hook**：输入索引与关键行为。

### 安排职责

**Input**：当前任务约定、依赖及可用角色。**Goal**：每项必要职责有负责人、允许改动范围和交接目标。**Guidance**：按命题和依赖拆分，不可分时保留一个执行者；派发使用 [dispatch.md](templates/dispatch.md) 及对应角色模板。隔离判断以不继承历史方式创建，Codex 使用 `collaboration.spawn_agent` 的 `fork_turns="none"`；其他宿主使用等效真实工具。**Execution Mode**：军团长派发；执行模板见 [executor.md](templates/executor.md)。**Audit Hook**：派发、实际消费版本与子调用摘要。

### 承接产物

**Input**：执行者明确 ready 的产物、依赖版本和自检。**Goal**：发布、主控接受与消费者实际使用三个事实可追溯。**Guidance**：读取正文并核对路径和指纹；草稿不当正式版；组合正确性不等于局部完成相加。监督可检查主控，用 [supervisor.md](templates/supervisor.md) 追踪需回应发现。**Execution Mode**：执行者产出、军团长集成、监督按需检查。**Audit Hook**：交接、影响与发现/回应。

### 取得证据

**Input**：当前合法标准、当前产物、环境和未闭合发现。**Goal**：独立结论与实际检查证据对应准确版本。**Guidance**：用 [verifier.md](templates/verifier.md)；结果直接进入交付判断。失败交回原目标内修复；更改阶段成功条件交战略，更改用户保留要求交用户。接受带限制交付不能把失败改成通过。旧回执须检查对应范围与指纹，变更后按影响复核；保存原不利结果。**Execution Mode**：独立验证者；缺独立承接则保留未验证。**Audit Hook**：原始检查、失败、当前指纹及结果与验证。

### 交付与接手

**Input**：当前有效证据、剩余项与停止条件。**Goal**：分别记录 `delivered`、`goal_achieved`、`stop_reason`，向用户交付产物、用法、验证及剩余影响。**Guidance**：有限任务按条件关闭，不自动增开优化；持续服务单独记录来源、期限、运行责任人、健康和终止条件，一个事件完成不终止服务。无调度器不承诺会话后运行；负责人不可达按既有替补，结果不明动作先查结果；不依赖缺失决定的已授权工作可继续。**Execution Mode**：军团长，阶段续行交战略。**Audit Hook**：关闭/接手、资源索引和日志封口。
