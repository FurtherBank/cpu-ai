# 执行团队任务

## 接住目标

**Input**：用户原始任务、可访问的现状与有效变更、宿主工具。**Goal**：形成当前任务约定，包含目标、授权和范围、成功/停止条件、现状引用及会改变走向的未知。**Guidance**：先查已有材料；需要改用户保留目标或扩大授权时才交用户。有跨阶段取舍时将原文和证据交独立战略，不把普通分工变成战略审批。新会话先核实已有任务句柄与最新输入，状态文件不算存活证据。**Execution Mode**：军团长主控；输出保存在运行目录的 task.md，原文或稳定引用不可缺。**Audit Hook**：更新输入索引和关键行为。

## 安排职责

**Input**：task.md、真实依赖、可用并发与角色工具。**Goal**：每项必要职责有负责人、边界与交接目标。**Guidance**：按命题和依赖拆分，耦合太紧就保留一个执行者；需要独立战略、监督或验证时启用独立实例。使用 ../templates/dispatch.md 和对应角色文件；隔离判断以无历史继承方式创建（Codex 为 fork_turns="none"），给原始需求全文或准确版本引用。先确认角色可读所给路径。额度不足串行；没有真实子 Agent 就记录能力缺口，不把自检改称独立验证。**Execution Mode**：军团长派发；执行者不擅自再派团队。**Audit Hook**：记录派发与实际消费版本；纯委派在父日志一行记录，显式子 Skill 带其日志路径。

## 承接产物

**Input**：执行者发布的产物、依赖版本和自检。**Goal**：军团长读过并接受明确发布版，消费者确认实际使用版，待解决影响可指认。**Guidance**：草稿不当交付；记录路径与内容指纹，文件可在项目正常位置，变更后重新交接。检查组合而非只加总局部通过。监督发现写清预期、实际、证据、影响、责任人和回应；可采纳或有据驳回，未响应按决定归属升级。监督覆盖主控，普通发现不自行改目标/接管。**Execution Mode**：执行者产出、军团长集成，独立监督按异常或关键交接启用。**Audit Hook**：更新交接、影响与发现/回应。

## 取得证据

**Input**：当前合法 task.md 和相关判据、当前产物、环境、未闭合发现。**Goal**：取得范围明确的独立通过/失败/未验证结论及实际证据。**Guidance**：验证者从真实用户路径检查目标与回归，可补选用例，结果直接交军团长。失败由军团长安排原目标内修复；事实错误按证据复核，验证结论的更正仍由验证职责另发。改阶段成功条件交战略，改用户保留要求交用户；接受残余问题不能把失败改为通过。工具回执只核对内容与环境声明一致性，不判断语义、覆盖或验证者身份。**Execution Mode**：独立验证者；不具备所需独立承接时保留未验证，继续有独立授权的准备工作。**Audit Hook**：保留原始检查、失败、当前指纹和结果与验证。

## 交付与接手

**Input**：当前证据、未决事项和停止条件。**Goal**：分别记录 delivered、goal_achieved、stop_reason 并交付产物/使用方式/证据/剩余影响。**Guidance**：军团长负责完整路径，战略负责授权内阶段续行；有限任务完成后关闭，不自动增开里程碑。持续服务另记目标、来源、期限、运行负责人、健康与终止条件，一个事件结束不终止服务。接手时回查原文、当前版本、未闭合发现与实际句柄；没有调度器仅承诺当前会话可完成部分，持续要求保持未满足而不擅自改为一次性。结果不明的已提交动作先查实际结果。**Execution Mode**：军团长；失效替补按既有授权，不可达时仅限制依赖缺失决定的动作。**Audit Hook**：更新关闭/接手、所有实际影响及其当前处置、结果与资源索引，封口日志。
