# 行为日志与运行质量

采用 behavior-log/v1，包内骨架可直接复制。日志置于工作区 `.skill-logs/agent-team/yyyy-mm-dd/hhmm-任务短名.md`，任务短名在创建时确定；同名追加序号。执行 ID 使用 `BL-开始时间-agent-team-任务短名`。运行目录保存交付与任务状态，日志仅通过资源索引链接，不复制正文。

固定章节顺序：`顶层执行摘要`、`执行边界`、`依据与关键输入`、`关键行为`、`子 Skill 调用`、`影响清单`、`结果与验证`、`偏离、异常与未决事项`、`资源索引`、`更正记录`。元数据含规范版本、执行 ID、Skill、状态、开始/更新时间、完成时间、工作区和执行目标。

| 阶段 | 应能从日志及所指制品核对什么 |
| --- | --- |
| 接住目标 | 原文与当前约定、授权、成功/停止条件、关键未知 |
| 安排职责 | 真实角色与工具、派发边界、依赖、原文及实际版本 |
| 承接产物 | 发布 ready、主控接受、消费者使用及发现/回应 |
| 取得证据 | 标准、当前产物与环境、实际验证、原失败及复核 |
| 交付与接手 | 交付/达成/停止原因、剩余影响、接手引用及实时核实边界 |

记录材料性决定、发布、失败、重试、降级、授权变化和影响。纯委派在父日志一行留证；显式子 Skill 收集子日志路径与影响，缺失则记审计缺口。日志不是实时进程表，也不是语义验收结论。

封口前逐项核对：固定章节齐备；无未替换占位；五阶段有对应记录或有据跳过；实际影响全部登记；验证范围与结论一致；交付与日志资源相互可定位；子调用链可查；未决与失败未消失。记录每项通过/失败及证据位置。写入终态与完成时间后再核对状态和资源链接；发现错误在更正记录追加修复并重新封口。日志可以封口为成功、部分成功或未完成，业务目标达成另列，不把审计完整当业务完成。
