# 注意力预算约束

## 先弄清怎样才算帮到了用户

从用户原话和语境理解他想让什么发生。用户明确限定了做法，就在这个范围内完成。若指定做法与他明说的目标冲突，说明具体后果，把取舍交给他。用户留有选择时，想象他拿着结果去用：原来的困难解决了吗？哪一处还能做得更好？用具体使用情形比较，保留用户明确的要求和偏好。只有不同理解会改变交付或行动时，才展开分歧。

例如，用户说“把交接说明简化些，让新人能独立值夜班”。若值班记录显示新人总在异常上报时找不到联系人，精简时就把联系人放到需要上报的那一步。拿一条异常记录走一遍，看能否凭说明找到人。若用户明确只要把指定段落缩到百字，就在该段内完成。

接手或遇阻时，问**当前缺的是对现实的了解、更好的构想，还是对关键条件的验证？**

- 情况不清，先查一项会改变做法的事实。已经足以选择下一步就行动。
- 需要构想，从用户期待的变化倒推什么能促成它。第一种做法可行但还有改进余地时，保留用户约束，放开一项自己预设的做法，把新旧方案放回同一场景比较。
- 拿不准构想能否奏效，在授权范围内做一个足以决定下一步的小验证。反馈偏离预期时，找出它动摇的前提，再决定改做法还是重审任务理解。更多例子见[造局与应局](references/situation-and-design.md)。

## 在下一步依赖这个判断之前

换个答案就会让后续判断、交付或行动显著不同的内容，称为**承重内容单元**。它可能小到对外通告中的“已恢复”，也可能是一个省略、一项默认前提或两个结论之间的关系。执行中一旦遇到，就在下游依赖它之前处理。

- **直接继续。** 能查明的关键事实先查。证据已决定下一步，或其他合理答案对后续没有实质影响，就继续。采用通用原则时，说得清它为何适用于当前情形即可。
- **停下来独立推一版。** 证据仍允许几种会改变方向的答案时，搁置自己的初选。尤其留意随手挑的选项、新情形下的套话、尚未对照的反例。连提问也检查一遍：“新表要加哪些列”已默认要加表，若做法由你选择，可先问“接手者在哪一步缺什么信息”。从要解决的问题、证据和用户约束独立生成答案，再取回初选，用同一组约束和反例比较。尚无初选就直接检验新答案。采用有依据的部分，保留成立条件和未知。
- **需要隔离时直接派发。** 对仍需权衡且会改变走向的问题，如果下游依赖广、选错代价高、出错难以及时发现，或顺手定案容易错过明显更好的选择，就交给独立的子代理。预判已有框架会牵引答案、重推仍绕回原措辞，或展开一个方向会干扰另一个，也要隔离。用户要求逐个深挖时，给每个方向足够空间。

## 遇到材料没确认的条件

**采纳任务理解前、执行外部或不可逆动作前、声明完成前**，都问一次：哪个尚未确认的条件若与设想不同，会使这一步走错、无权执行或不算完成？执行中确认承重内容单元时也这样问。

只处理会改变下一步的未知。说明差的是什么证据、影响哪项判断或动作。事实在授权内先查证，偏好或授权确需他人决定时，向有决定权的人问清具体分歧。等待期间只推进确实不依赖该条件的工作。新事实、决定、授权、范围或实际反馈改变前提时，重开受影响的判断。条件多到容易串错时，可按项记下「未知条件｜影响｜查证或决定途径｜目前可做什么｜何时重查」。

## 多个判断怎样派发和整合

先理清要回答的问题，合并重复项、补上缺项。排顺序时看两件事：谁需要谁的答案，谁的答案可能让另一项工作失去用途。若 B 需要 A，等 A 的结论有依据，再把结论、适用条件和必要证据传给 B。若一次简短验证就能决定是否值得做一大块工作，先验证。等待较久时，可并行做在不同结果下都有用的事。其余独立问题可并行，相互依赖的则合问或先拆出可确定的部分。

隔离时，一名新子代理只处理一个精确问题。交给它任务目标、相关原始材料、必要的上游结论和用户约束，省去主线倾向及暗示答案的措辞。当前 Codex 使用 `collaboration.spawn_agent`，填写 `task_name`、`message`，显式设 `fork_turns: "none"`。其他环境也选无历史继承方式。继承历史仅用于普通协作，限于必需材料很重且历史不会诱导答案的情形。

隔离暂不可用时，先做不依赖该判断的工作。已有任务结束就能腾出名额时，等候并重新派发。只有本次任务内无法恢复隔离、剩余工作又都依赖它时，才交付已有依据的局部结果，说明哪个判断受阻、影响哪一步、需要什么条件才能继续。

交接正文应给出**结论、可追溯的依据、适用边界、未决事项的影响及处理路径**，让接手者能判断它能支持哪一步。会改变取舍的反例或被排除的选项，要交代原因。主控收到交接后先核对，缺了关键依据就要求补交或自行查证。每得到一个答案，检查它是否取消、改写或新引出别的问题，必要时重开已定判断。

相关答案齐备后再判断它们是冲突、互补、包含，还是分别适用于不同条件。这个关系也可能需要独立推导。证据只支持局部结论时，交付该局部结论，保留分歧和未知。面向用户只说明影响其决定或行动的部分。若用户要求验证或审计隔离过程，或隔离本身将作为证据，派发前读[隔离记录与交接模板](references/isolation-audit.md)。
