# 隔离记录与交接模板

在实验、验证或审计中需要证明独立推导确实发生时，从第一次派发起保存下列可核对的记录。普通交接采用主文里的简短正文即可。

| 何时记录 | 需要留下什么 |
| --- | --- |
| 选定问题时 | 最初识别出的判断或候选方向，以及舍弃某个方向的依据。 |
| 派发时 | 每个问题的完整派发文本、实际工具和参数、是否继承历史，以及传入的材料和上游结论。 |
| 收到交接时 | 与该次派发对应的最终正文，或可读取的完整交付文件路径。用原始交付核对进度消息里的说法。 |
| 整合前 | 哪些答案相互支持、冲突、包含或各有适用条件，依据是什么，还有哪项关系无法确定。 |

把记录留在任务约定的位置或随结果交回。材料多时可让子代理写入指定的工作文件，并在最终消息给出路径与摘要；主控读文件后再整合。无法写文件时，用自包含的最终正文。记录缺失时标明缺哪项、因此哪一段过程无法验证。

## 向子代理索取可复查的交接

可将下面这段附在审计任务的派发文本末尾。各节可随内容长短伸缩。

> 最终正文从 `## 结论` 开始，依次使用以下标题。接手者凭派发文本和这份交接，应能回查依据、理解取舍并判断结论能支持哪一步。
>
> **结论**　给出本问题的判断，每条附证据出处和采用理由。
>
> **备选与反例**　写出影响取舍的备选或反例，以及为何排除或保留。
>
> **适用边界**　写清成立条件，区别哪些有实证、哪些来自推断、哪些仍未知。
>
> **未决事项**　说明缺什么、影响哪个结论或动作、下一步怎样查证或由谁决定。
>
> **交接摘要**　用不超过 150 字概括可用的判断及其关键边界。

主控逐项核对交接能否独立读懂、证据能否定位。审计模板要求固定标题和摘要长度时，一并核对。交接不合格时，在同一会话指出缺项并要求补交，最多两次；仍不足就用干净输入重新派发该问题。在取得合格交接前，将依赖它的综合结论保留为未决。
