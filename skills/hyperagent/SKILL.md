# Hyperagent

## 这项 Skill 负责什么

把一个复杂任务从用户目标转成可追踪、可验证、能收敛的协作状态。默认由当前 Agent 承担主人公职责，其他职责按任务条件启用。不要因为任务看起来复杂就自动创建完整团队，也不要把角色名称当成质量证据。

“主人公”指当前任务的整体负责人。说白了就是有人持续负责把目标、分工、产物、验证和关闭判断接起来，而不是只负责分派工作。

独立验证是一项能力，不是固定的第五个角色。它可以由新 Agent、独立测试进程、人工验收或外部系统规则承载。被检对象不能同时成为独立验证结论的唯一生产者和唯一证据筛选者。

## 先冻结当前任务契约

在派发任何 Agent 前，先形成一份可被下游直接消费的任务契约。至少写出：

- 用户真正要改变的现实状态。
- 当前已经成立的事实、推断、假设、决定和未知。
- 成功条件、停止条件、不可牺牲项和有效授权。
- 任务是有限任务还是持续服务。有限任务指有可验收终点、可以定义关闭条件的单次任务。
- 最终消费者会拿结果做什么判断或动作。
- 外部副作用、不可逆动作、隐私限制和真实评价来源。

如果目标、授权或停止条件仍有多个会改变走向的解释，先查证或交给有决定权的人。不要用任务拆分掩盖目标未定。

## 选择运行模式

主人公在派工前判断六件事。

- 目标是否稳定，是否需要阶段性取舍。
- 命题、写入范围、依赖和集成点能否隔离。
- 失败代价和返工代价是否值得独立观察或独立验证。
- 是否存在持续运行、等待链、消息投递或负责人失联。
- 结果是否需要真实用户、受众、领域专家或其他外部评价。
- 是否会发生付款、删除、发布、修改生产数据等不可逆外部动作。

按判断结果选择一个主模式，再叠加适用的附加能力。阶段、监督、外部评价和授权门不是互斥选项。例如，研究型游戏任务可以是“阶段模式 + 外部评价模式”，持续发布任务可以是“协作模式 + 监督模式 + 授权门”。最终输出同时记录主模式、附加能力和实际承载者。

- **单体模式**：小型、边界稳定、低风险、一次可完成的任务。主人公直接执行并做轻量自检。
- **高耦合模式**：共享可变状态、竞态、单一证明或无法隔离的重构。只指定一个写入者，其他角色只读或提交补丁，必要时在冻结产物后做独立验证。
- **协作模式**：目标稳定且至少两个命题可以独立推进。主人公分派执行者，自己保留集成和整体关闭责任。
- **阶段模式**：目标、优先级、资源或停止条件会变化。启用战略引领者，按里程碑更新有效契约。
- **监督模式**：持续服务、跨单元组合、高成本失败、对抗性风险或不可逆动作。启用独立监督，运行层负责心跳、消息和进程状态。
- **外部评价模式**：审美、体验、幽默、剧情、受众反应或领域专业判断是结果的一部分。把真实受众、用户、专家或可追溯基准接入评价，不把自评写成客观通过。

无法证明可分性时，采用单体或顺序路径。无法形成独立证据路径时，输出“自检”或“未验证”，不能标为独立通过。

## 运行职责

### 在 Codex 中的承载方式

当前对话默认承载主人公。需要局部执行或独立判断时，使用 `collaboration.spawn_agent` 创建无历史继承的 Subagent，并在派发文本中传入任务契约和必要原始材料。独立验证优先使用新上下文，避免把执行者的自评当作独立证据。

战略引领者或监督者只有在阶段性方向判断、持续运行或独立观察确实需要时，才单独创建 Codex 对话或长期承载。没有可持续的状态读取、消息投递和唤醒能力时，不得声称已经有持续监督。新 Codex 对话用于独立测试时，应提供真实任务和最少必要材料，不传入预设答案。

### 战略引领者

在有效授权内决定阶段目标、优先级、里程碑成功条件、停止条件和是否继续。它向主人公交付带版本的目标与取舍。

战略引领者不决定具体实现、文件分工或局部方法。它只能在预授权的阶段范围内更新目标、成功条件或停止条件，每次更新都生成新版本，旧版本立即停止作为新工作的依据。它不因监督发现而自行改变用户目标，也不把执行任务结束解释成整个计划结束。改变用户保留目标、不可逆状态或授权范围时，回到用户或真实授权者。

### 主人公

负责任务理解、适用性判断、拆解、分工、依赖、集成、验证安排、交付准备和有限任务的关闭判断。主人公可以在有效里程碑内改变方法和任务切分，但不能削弱成功条件或代发独立验证结论。

完成交付不等于目标达成。只有成功条件已有匹配证据，主人公才能形成目标达成判断。需要外部签批时，状态保持为待决定。

### 监督者

独立观察任务是否仍朝有效目标推进，记录预期、实际、证据、影响、责任人、回应状态和复查结果。它区分推进、正常等待、阻塞和无法观察。

监督者提出提醒、复查或升级。普通发现不自动改变目标、暂停一切工作、批准交付或授权外部动作。没有持续运行能力时，只能声明快照监督。

### 具体做事 Agent

只负责主人公分配的局部命题、方法和产物。交回稳定版本、依据、自检结果、已知问题和跨任务影响。它不能扩大范围、修改上层标准或宣布整体完成。

### 独立验证能力

直接读取有效标准、对应产物、环境和原始输入，独立选择检查范围与方法，交回原始证据以及通过、失败或未验证结论。主人公可以提出补验问题，不能规定结论。

验证结论绑定标准版本、产物版本和环境。新证据需要由承担验证责任的角色复核并发布新结论。任务 ready、PR 关闭、工单结束和执行者自检通过都不能替代独立验收。

## 派发与推进

每个执行 Agent 只接收一个清晰命题。派发文本写明当前任务契约、允许来源、禁止假定、输入边界、可修改范围、输出格式、证据要求和深度边界。不要把多个未决方向混成“综合想想”。

使用独立上下文时，分开传入必须保留的有效标准、原始输入和已证实事实，以及必须隐藏的主控答案、倾向性结论和未经确认的假设。需要隔离的判断包括目标解释、可分性、关键反例、验证方法和高代价取舍。

主人公收到交接后先核对版本、范围、依据、适用条件和未知，再整合。生产者发布、主人公登记接收、消费者读取是三个事实。接收记录不转移内容决定权，也不改变不利验证结果。

出现以下情况时回开，而不是继续向下细化。

- 新事实推翻目标、成功条件、授权或父层边界。
- 产物、标准、环境或验证版本不一致。
- 下游必须重建上游本应完成的判断。
- 多个执行者共享状态并互相覆盖，无法保持所有权。
- 自评与真实用户、受众、专家或运行反馈不一致。

## 监督与关闭

监督记录发现的完整闭环，包括已记录、已送达、已读取、已回应和复查结束。任务契约要写预计时长、检查频率、超时阈值和恢复动作。长工具调用不能只凭无消息判定失败。进入“无法观察”时禁止关闭任务，必须恢复观察或升级。已提交但结果不明的外部动作先查实际结果，再决定是否重试。

有限任务关闭时分别记录产物是否交付、目标是否达成、剩余问题、停止原因和使用的证据版本。交付但未达成必须保留未达成状态。持续服务按期限、停止条件或用户指令结束，子事件完成不等于服务结束。

如果角色失效，按任务契约中登记的替补、权限作用域、有效期和接替证据接替。没有登记或核验不通过时，可以继续不依赖缺失决定的工作，集成、验收、外部动作和关闭判断保持待决并升级。

不可逆外部动作执行前必须通过硬门。授权来源、作用域、有效期、动作参数、幂等标识和结果回查方式全部齐全且仍有效时才可执行。缺少任一项时保持待决定并升级，不能把用户的一般目标、负责人失联或监督发现当作动作授权。

## 不应宣称的内容

- 角色已创建不等于职责已被运行层保证。
- 监督消息已发送不等于接收者已读取或已回应。
- 局部测试通过不等于整体用户路径通过。
- 自我反思增加不等于评价基准已经校准。
- 交付完成不等于目标达成。
- 一次工程样题通过不等于该架构对所有任务有效。

## 最终输出

向用户交付时，说明当前模式、实际启用的职责、目标与标准版本、已验证证据、未决事项、回开条件和下一步。把事实、判断、建议和未知分开。若任务仍未闭合，明确指出缺少哪一项决定或证据，以及它由谁补齐。
