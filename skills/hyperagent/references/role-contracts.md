# 职责契约

## 决定对象矩阵

| 承载方式 | 负责什么 | 输入 | 输出 | 不得承担 |
| --- | --- | --- | --- | --- |
| 战略引领者 | 阶段目标、优先级、里程碑成功条件、停止条件 | 用户授权、阶段成果、环境变化、关键未知 | 目标与取舍版本 | 具体实现、局部方法、无授权的目标扩张 |
| 主人公 | 任务理解、可分性判断、分工、集成、整体交付判断 | 当前有效目标、执行产物、验证证据、监督发现 | 任务网络、组合产物、关闭判断 | 削弱成功条件、代发独立验证结论 |
| 监督者 | 偏航、阻塞、遗漏、失联和观察缺口的发现与升级 | 目标、活动记录、运行状态、证据 | 发现、责任人、回应状态、升级路径 | 自动改目标、替代修复、批准外部动作 |
| 执行 Agent | 分配命题内的方法和局部产物 | 命题、输入、依赖、约束、可修改范围 | 产物、依据、自检、已知问题 | 扩大范围、改标准、宣布整体完成 |
| 独立验证能力 | 选择检查方法并判断结果是否满足标准 | 有效标准、产物、环境、原始输入 | 原始证据、通过、失败或未验证 | 被检对象单独筛选证据、代替用户接受风险 |

## 关键权限边界

### 目标与方法

战略引领者可以改变阶段目标、成功条件和停止条件。主人公可以在这些条件内改变方法、任务切分、组件映射和证据组织。执行 Agent 只能改变分配范围内的实现。

“跨文件”“跨模块”“跨任务单元”本身不决定上提。只有当变更打破调用者预期、改变模块职责、改变里程碑成功条件或扩大用户授权时，才需要上提。

### 交付与达成

主人公负责在有效授权和证据范围内形成整体交付判断。交付、目标达成和任务关闭分别记录。缺少成功条件证据时，可以交付为“未达成”或“待决定”，不能把交付状态写成达成状态。

### 验证独立性

验证独立性来自生产者与验证者的分离、证据路径和判断权限，不来自角色名称。验证者不能同时是被检产物的唯一生产者和唯一证据筛选者。完成下列任一独立路径后，才可标为独立验证，并记录采用哪一项。

- 与生产者不同的验证者直接读取原始产物，而不是只读取执行者摘要。
- 与生产者不同的验证者独立选择检查范围或方法。
- 验证结果绕过被检对象直接进入整体交付判断，并由不同的证据筛选者消费。
- 验证在独立进程、人工验收或外部系统规则中完成，且生产者不能修改其结果或筛选其原始证据。

如果不能证明生产者与验证者的职责分离，结论标为自检或未验证。例子是执行 Agent 写完网页后自己换一套截图标准并宣布“独立通过”，这仍然是自检。

### 监督与运行层

运行层承载心跳、进程状态、消息投递、唤醒和权限门。监督者承载语义判断、影响分析、责任分配和升级。运行层状态不能直接替代语义监督，监督发现也不能自动获得运行层的执行权限。

### 外部授权

付款、删除、发布、修改生产数据、对外承诺和接受高风险残余问题等动作，都要记录决定者、作用域、有效期、动作参数、幂等标识和结果回查方式。全部字段齐全且仍有效才放行动作。负责人失联不自动撤销已经生效的授权，也不自动产生新的授权。缺字段或过期时保持待决定并升级。

## 角色承载

| 职责 | 可与当前 Agent 同实例 | 是否必须独立证据路径 | 启用证据 |
| --- | --- | --- | --- |
| 主人公 | 默认可以 | 否 | 当前 Agent 持有整体任务契约并负责集成 |
| 战略引领者 | 稳定目标的小任务可以合并 | 否 | 新目标版本和授权来源 |
| 监督者 | 短任务可不启用，启用时通常独立 | 是 | 可读取运行状态、发现记录和回应链 |
| 执行 Agent | 可以由主人公直接执行 | 否 | 清晰命题、所有权和交接产物 |
| 独立验证能力 | 不能与被检产物的唯一生产者同实例 | 是 | 原始产物、独立方法或独立执行路径 |

监督者可以兼任验证者，但必须额外满足独立验证条件，单独发布验证结论。监督发现本身只能用于发现和升级，不能直接充当验收证据。

角色名称写入记录不等于职责已经启用。启用记录必须写出承载者和可核对证据。
