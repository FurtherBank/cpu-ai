# 任务模式与适用性

## 启用判定

主人公至少回答下表问题，再决定是否派发。

| 判断 | 需要什么证据 | 对模式的影响 |
| --- | --- | --- |
| 目标是否稳定 | 有效目标、成功条件、停止条件和授权版本 | 不稳定时进入阶段模式或先交回方向决定 |
| 是否可分 | 每个命题、写入范围、依赖和集成点 | 不可分时采用单体或顺序路径 |
| 是否需要独立验收 | 错误代价、作者偏差、客观标准和可复现环境 | 需要时启用独立验证能力 |
| 是否持续运行 | 期限、心跳、等待链、唤醒、接替和停止条件 | 需要时启用监督模式与服务负责人 |
| 是否存在真实外部评价 | 用户、受众、专家、基准数据或现场反馈 | 内部自评不能作为唯一质量依据 |
| 是否有不可逆副作用 | 生产环境、付款、删除、发布、隐私和合规约束 | 需要授权门和结果回查 |

## 常见模式

以下模式按维度叠加。主模式描述任务的主要组织方式，附加能力描述需要额外满足的监督、评价或授权条件。

### 单体模式

适合短时、低风险、边界稳定、一次完成的任务。当前 Agent 同时承担主人公和执行者，做必要的自检。外部监督和独立验证只有在错误代价或用户要求触发时才启用。

### 高耦合模式

适合共享可变状态、竞态、单一证明、单一迁移和无法隔离的重构。默认只有一个写入者，其他角色只读或提交补丁。独立验证可以在产物冻结后读取结果，但不要强行并行。

### 协作模式

适合目标稳定、至少两个命题可以独立推进、每个命题有明确所有权的任务。主人公承担集成、组合验收和关闭判断。局部负责人不能相加为整体负责人。

### 阶段模式

适合研究、产品演进和长周期设计。战略引领者为里程碑提供目标、取舍和停止条件。假设必须显式标记，事实变化不自动等于目标变化。

### 监督模式

适合持续服务、跨单元组合、高成本失败、对抗性风险和不可逆动作。监督者独立读取状态并追踪回应，运行层负责可观察性与唤醒。只有同时具备状态读取、定期检查、消息投递、唤醒、接替和停止条件时，才可声明持续监督。缺少其中任一项时降级为快照监督或未观察，并禁止在无法观察时关闭任务。

### 外部评价模式

适合网页体验、视觉风格、游戏、剧情、幽默、内容效果和领域专业判断。把真实用户、受众、专家、参考样本或可复现实验接入评价。内部反思只能生成假设，不能证明感知已经校准。

## 不适合完整分工的情形

- 原子任务的交接成本高于任务本身。收缩为单体模式。
- 多个 Agent 必须同时修改同一共享状态。改为单一写入者或先重建隔离环境。
- 成功条件依赖真实受众或持证专家。引入评价来源，不能只增加内部验证者。
- 事故窗口很短。使用预置授权和单一操作负责人，监督旁路记录，验证后置或并行。
- 高风险领域需要法定决定权。引入真实专家或人类最终批准者，Agent 只准备材料和按标准复核。
- 任务包含隐私限制，验证者不能读取必要数据。使用脱敏工件、合成数据或隔离复现，并把访问不足标为未验证。
