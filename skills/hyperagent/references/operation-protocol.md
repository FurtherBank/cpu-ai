# 协作、监督与关闭协议

## 任务契约

```markdown
任务目标：
任务类型：有限任务 / 持续服务
成功条件：
停止条件：
不可牺牲项：
有效授权与版本：
当前事实：
推断与假设：
未知：
最终消费者：
外部副作用与评价来源：
当前运行模式：
附加能力：
预计时长、检查频率与超时：
替补、权限作用域与有效期：
```

## 派发契约

每次只派一个命题、一个透镜或一条承重边。派发文本至少包含：

- 当前任务契约和上游已确认结论。
- 本 Agent 允许读取的原始材料和禁止假定。
- 输入边界、可修改范围、深度边界和输出格式。
- 完成标准、证据要求、适用条件和回开触发条件。
- 是否使用独立上下文，以及不应传入的主控倾向。

这里的“主控”即当前任务的主人公。验证派发要分开写明必须传入的标准、原始输入和已证实事实，以及必须隐藏的答案、倾向和未经确认假设。

交接正文至少包含结论、证据出处、备选与反例、适用边界、未决事项和交接摘要。主控核对后才能把它作为下游输入。

## 版本交接

承重产物至少记录内容指纹、适用任务、目标版本、标准版本、环境版本、生产者、发布状态、接收状态和实际消费者。生产者发布、主人公接收、消费者读取是三个不同事实。

发现版本失配时，暂停依赖该版本的新判断或动作，保留仍有独立依据的工作，重新发布、接收和消费。旧失配、不利报告和争议不能被新的接收记录抹除。

## 监督记录

```markdown
发现编号：
观察时间：
预期状态：
实际状态：
证据位置：
影响：
责任人：
需要的决定：
状态：已记录 / 已送达 / 已读取 / 已回应 / 复查结束
升级路径：
回开位置：
```

“无消息”只说明当前缺少消息。只有结合进程状态、预计时长、检查频率、超时阈值、最后观察时间和恢复条件，才能判断等待、阻塞或无法观察。无法观察时禁止关闭任务。

## 关闭记录

```markdown
产物是否交付：
目标是否达成：
使用的目标、标准、产物和环境版本：
消费者已读取及其判断结果：
已验证证据：
剩余问题：
接受残余问题的决定者：
停止原因：
后续移交：
```

已交付但未达成必须保留未达成状态。持续服务要单独记录服务目标、期限、运行责任人、事件状态和停止条件，子事件关闭不等于服务关闭。

如果目标依赖消费者实际读取、操作或签批，而该事实尚未发生，最多交付产物，目标保持待定或未达成。
